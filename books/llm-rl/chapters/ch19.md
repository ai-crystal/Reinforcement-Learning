## 评测、复现与收尾

训练完了，怎么知道有没有变好？

这个问题看起来简单，实际上是大模型研究里争议最多的部分。同一个模型，不同的评测方式能得出完全相反的结论。

这一章讲几个关键的坑，以及一套可操作的评估流程。

### 常用的基准

数学方面，GSM8K 是小学数学应用题，AIME 是竞赛题，MATH 覆盖更广的难度。代码方面，HumanEval 和 LiveCodeBench 是常用的，后者用较新的题目，减少污染。

这些基准各有各的问题。GSM8K 已经被刷得很高，区分度不够。AIME 题目少，方差大，同一模型不同次运行差别明显。LiveCodeBench 相对好一些，但也在被逐渐攻破。

### 一个基准的三段寿命

基准是有寿命的。它的曲线大致分三段。

第一段是好用期。当时最强的模型只能做到一半不到，题目和模型的差距大，每个改进都能在分数上看出来。这个阶段基准能分辨好坏。

第二段是拥挤期。分数挤到八成以上，剩下的题都很难，改进从十个点变成两个点，而两个点在采样噪声里。这个阶段基准还能排个大概顺序，但已经不适合做细致的消融。

第三段是饱和期。分数到了九十几，剩下的错题里很多是题目本身有问题，或者标注有争议。这时候再涨一个点，往往不是模型变强，而是模型正好和标注者的习惯对上了。

判断到了哪一段，看两个东西。一是分数的标准差，高分段的方差小，一个小改进就能把排名翻过来。二是错题的质量，把错的那几道拿出来人工看，如果一半是题目或标注的问题，这个基准已经没用了。

三段各有用途。拥挤期适合对外报一个数，饱和期只能当回归测试用，看模型有没有把以前会的忘掉。真正能看出能力的，是那些刚发布、分数还在三四十的基准。代价是它们题目少，方差大。

用这些基准时要注意版本和提示格式。同一个模型，换个提示模板，分数可能差几个点。所以比较时要用相同的设置。

### pass@k

代码任务常用的指标是 pass@k，意思是生成 $k$ 个候选，至少有一个通过测试的概率。

无偏估计的公式是

$$
\text{pass@}k = \mathbb{E}_{\text{题目}}\left[1 - \frac{\binom{n-c}{k}}{\binom{n}{k}}\right]
$$

$n$ 是采样总数，$c$ 是通过的数量。这个公式避免了直接用“通过数除以采样数”带来的偏差。

pass@1 是最严格的指标，只看第一个答案。pass@k 随 $k$ 增大而上升，所以报数字时必须说明 $k$。

有些报告只报 pass@100 而不报 pass@1，这会让结果显得比实际好。读的时候要注意。

### 估计这个公式到底在纠什么偏

上面那个组合数的形式看起来奇怪，它解决的是一个很具体的问题。

采样 $n$ 条，通过 $c$ 条，想知道“如果只采 $k$ 条，至少一条对的概率”。直接的想法是用通过率 $c/n$ 去估单条成功率，再算 $1-(1-c/n)^k$。这个做法有偏，而且偏得不小。

拿一组具体参数算。单条成功率零点五，采十条，问 $k$ 等于五时的 pass@5。真值是 $1-0.5^5$，等于零点九六八八。

用组合数公式估，得到零点九六八八，对得上。用上面那个直接想法估，得到零点九三三一，低了三个多点。偏差的原因很直白，$c/n$ 只有十个样本，本身就有波动，而 $1-(1-p)^5$ 是凹函数，波动经过它就被压小了。

这个偏差在中段最明显。$c$ 等于四时，无偏估计给零点九七六，直接估法只给零点九二二。$c$ 等于五时，两者是零点九九六和零点九六九。差距都出在同一个地方，$c/n$ 的波动被凹函数压小了一截。

```python
import math

def pass_at_k(n, c, k):
    # unbiased estimate of pass@k from n samples with c correct
    if n - c < k:
        return 1.0
    return 1.0 - math.comb(n - c, k) / math.comb(n, k)


def plugin(n, c, k):
    # the tempting shortcut, biased downward for concave curves
    return 1.0 - (1.0 - c / n) ** k
```

无偏不等于好用。估计的取值很粗。单条成功率零点五、采十条、算 pass@5，公式能给出的值只有七个，零、零点五、零点七七八、零点九一七、零点九七六、零点九九六、一。单题标准差零点零七，看起来不大，但那是因为 $p$ 等于零点五正好落在中间。

换成难题就露出来了。单条成功率零点二、采十条、算 pass@9，估计只可能是零、零点九、一这三个值，单题标准差零点三零。它仍然是无偏的，但每一道题的估计都很粗，题目少了平均不过来。

这就是为什么报 pass@k 要同时说 $n$。$k$ 越接近 $n$，能取的值越少，$n$ 越小，估计越粗。两个都不写，读者无法判断这个数能不能信。

所以报 pass@k 时必须同时说 $n$。只报 $k$ 不说 $n$，读者无法判断这个数有多不稳。

### 题目数量决定你能看出多大的差别

还有一个常被忽视的量，题目数。

在一组成功率均匀分布在零点零五到零点九五的题上做模拟，每题只采一条，算 pass@1。用五十道题，重复两百次，均值的九成区间是零点四零到零点六二。用一百道，零点四五到零点五九。用五百道，零点四八到零点五四。

这组数字的意思是，拿五十道题比两个模型，差五个点完全可能是噪声。一百道题，三个点以内不能下结论。五百道题，两个点以上才稳。

公共基准的题量恰好落在这些区间里。AIME 一年只有三十道，GSM8K 有一千多道，MATH 有五千道，HumanEval 只有一百六十四道。看到 HumanEval 上差两个点就说提升了，基本是在读噪声。

### 长度偏置

模型的回答变长，评测分数往往上升。原因是长回答有更多机会碰到正确答案，也有更多机会包含评分标准里的关键词。

如果不控制长度，比较两个模型就变成了比较谁写得更长。

常见的处理是在报告分数时同时报告平均长度，或者在评估时对长度做归一化。有些基准会限制最大长度，这能缓解问题但不能根除。

长度还有一个更隐蔽的作用，它会改变题目难度。同一个模型，给它更长的预算，它能写出更长的推理，正确率上升。所以两个模型对比时，长度预算必须一样，而且要比你想测的能力所需的长一点，不要让截断成为主要失败原因。

判断模型是不是靠长度拿分，有一个简单的做法。把每题的回答截到固定长度，比如一千 token，再判一次。如果分数掉得很多，说明它依赖长推理。掉得不多，说明长度只是风格。

### 数据污染

训练数据里如果包含了测试题，分数就不可信。

这种情况在大模型上很常见，因为预训练语料是从网上抓的，测试题和答案往往也在网上。

检测污染有几个办法。看模型在稍微改动的题目上表现如何，如果掉得厉害，说明它记住了原题。看训练数据里是否出现过测试题的片段。用新发布的、训练时不可能见过的题目。

LiveCodeBench 之所以流行，就是因为它持续更新题目，减少了污染的可能。

### 污染的四种形态

第一种是题目直接进训练集。题库里就有这道题，模型记住了答案。这种最好查，片段匹配就能抓到。

第二种是题目被改写。数字换了，背景换了，解法没变。片段匹配抓不到，只能靠语义近似加人工抽查。

第三种是答案泄漏。题面没进训练集，但标准答案的推导过程被写进了某个教程，模型读过。这类只能从答案侧查。

第四种是裁判污染。用模型当裁判时，裁判模型自己见过这批题和它们的标准答案，评分会向标准答案偏。这种最隐蔽，因为被污染的不是被测模型，是尺子。

四种污染的检查手段不一样，但有一个共同的处理原则，不要试图证明没污染，要假设有污染并设计能发现它的实验。比如拿同一批题做两个版本，一个原题，一个只改数字。两个版本的分数差距就是污染的上界估计。这个差距在一两个点内，可以接受。超过五个点，这个基准上的结论就不能用了。

### 一套可操作的流程

给一个模型做评估，可以按这个顺序。

先确定任务和指标。是准确率、通过率，还是人工评分。指标要和实际使用场景对应。

再固定评估设置。提示模板、采样温度、最大长度、采样次数，全部写下来。

然后跑多个种子或者多次采样，报告分布而不是单点。

这里有个具体尺度。三个种子能看出方向是否稳，五个种子能给出一个粗糙的区间。每多一个种子，成本线性上涨，而信息量下降得很快。公开报告里常见三个种子，内部决策建议五个。只有一个数字的报告，基本只能看个热闹。

种子只是方差的一个来源。另一个是数据划分，换一种划分方式，分数也会动。两个来源同时控，成本很高。实用做法是固定划分、多跑种子，至少在训练侧把随机性摸清。

最后做人工抽查。自动指标只能覆盖一部分，人工能发现指标看不到的问题，比如推理过程是否合理、回答是否真的有用。

### 一份报告该写清什么

把上面这些揉成一份可以照着填的清单。

:::

| 项 | 要写的内容 | 不写会怎样 |
| --- | --- | --- |
| 模型 | 参数量、检查点步数、是否量化 | 无法区分是哪一版 |
| 提示 | 模板原文、是否少样本 | 差几个点却不知道原因 |
| 采样 | 温度、最大长度、样本数 n、k | pass@k 无法交叉比较 |
| 解析 | 答案抽取规则、失败率 | 失败率藏在准确率里 |
| 长度 | 平均与九十分位输出长度 | 看不出是否靠长度拿分 |
| 污染 | 题库时间范围、检查方法 | 分数不可信 |
| 方差 | 种子数、区间或标准差 | 把噪声当提升 |

填完这张表，一篇报告的基本盘就有了。它不保证结论对，但至少别人能重跑一遍，能看出你的数字是在什么条件下得到的。

### 复现的三种程度

说到复现，很多人只有一个标准，就是数字一模一样。这个标准在大模型上基本做不到，也没必要。

可以分三层。

数值复现。同一个检查点、同一份数据、同一个脚本，跑出来的分数差在一个点以内。这一层是工程问题，应该做到。做不到说明流程里有不确定的地方，比如数据顺序、并行归约、非确定性的算子。

趋势复现。换一个种子、换一个数据划分，结论方向不变。比如加了长度惩罚确实变短了，加了大组大小确实变稳了。这一层是科学问题，比数值复现重要得多。

现象复现。在一个更小的模型、更小的数据上，看到同样的现象。比如奖励黑客在小模型上也会出现，只是出现得晚一些。这一层对理解机制最有价值，也是资源少的团队最该做的事。

三层里最容易做、最容易被跳过的是第二层。很多消融只跑一个种子，得到一个数就下结论。跑三个种子，你会发现问题里有一半的结论在符号上就不稳。

### 人工抽查怎么做

自动指标只能告诉你分数，人工才能告诉你怎么回事。但人工抽查很容易做成无用功，几个细节决定它值不值。

样本要随机抽，不能只抽错的。只抽错题，看到的是失败模式，看不到模型为什么在大多数题上对。正确做法是按结果分层，对的抽一成，错的抽全量。

要盲评。两个模型的答案混在一起，去掉标识，打乱顺序再给人看。不盲评的话，看的人会不自觉地偏向自己参与训的那个。这一条不要省，省了整份抽查报告的可信度就没了。

评分表不要太多项。三项就够，答案对不对，推理过程成不成立，回答有没有用。三项各三档，比十项五档好用，因为标注者的区分能力就那么细。

要记分歧。两个人标同一批，不一致的地方单独拉出来讨论。分歧集中的题目类型，往往就是自动指标失效的地方，比平均分有价值。

成本要算进去。看一百条回答，一人一天。一个季度做一次，比每周做一次但只看十条有用，因为十条看不出分布。

### 复现的难点

大模型的训练复现比小模型难得多。

算力是第一个障碍。一次完整的训练可能要几百张卡跑几周，多数团队做不起。

数据是第二个障碍。训练数据的构成往往不公开，比例、来源、清洗方式都不清楚。

超参数是第三个障碍。学习率、批次大小、KL 系数、采样温度，这些参数的组合空间很大，论文里给的只是其中一组。

所以复现大模型的工作，通常不是追求完全一致，而是验证趋势是否成立。在 smaller scale 上看到同样的现象，就算部分复现。

### 一个收尾前的提醒

写到这里，有一件事值得再说一遍，因为它比任何方法都容易被忽略。

强化学习的实验结果，对评估方式极其敏感。同一个模型，换一个提示模板、换一个答案抽取规则、换一个随机种子，结论可能从“明显提升”变成“没差别”。所以每次看到一个提升，先问三个问题，提升是多少，噪声有多大，测量方式是什么。

三个问题里最容易被跳过的是第二个。一个只有五拾道题的基准上，两个点的提升没有任何信息量。而很多“新方法”的卖点，恰好就是两三个点。

这不是说那些方法都不行，而是说单靠数字无法判断。想判断，得看它的机制能不能解释这个提升，能不能在小规模上重现，能不能在别的任务上看到同类现象。三个都对上，才值得跟进。

如果非要只记一句话，那就是这个。看到一个数字，先问它的误差有多大。误差比提升大的时候，那个提升不叫提升，叫抖动。

### 本书的收尾

书写到这里，可以回头看一眼走过的路。

开头把文本生成看成一个决策过程，一个 token 就是一步动作。接着讲奖励模型，人类偏好怎样变成一个可以自动打分的函数。然后进入训练，PPO 的工程现场、DPO 的化简、几个针对具体问题的变体。再往后是可验证奖励，RLVR 提供干净的信号，GRPO 省掉价值网络，公开的配方把流程跑通，测试时计算在推理阶段再加一层。刚过去的几章讲边界，奖励怎么被钻空子，多轮任务怎么训练，以及对齐训练本身要付的代价。

中间还夹着一部分容易被跳过的东西。预训练、微调、强化学习各自解决什么问题，奖励模型的偏好数据怎么造，PPO 在代码里怎么摆，DPO 的损失从哪一步解出来，可验证奖励的题目怎么筛，蒸馏怎么把能力搬到小模型上。这些不是算法，是让算法跑得起来的那层。

这条线里反复出现的其实只有三件事。怎么定义奖励，怎么在延迟和噪声中估计好坏，怎么在探索和稳定之间取舍。算法换了名字，这三件事没变。

如果读完之后，你看到一条新的强化学习新闻，能问出“奖励从哪来、样本从哪来、代价是什么”，这本书的目的就达到了。
