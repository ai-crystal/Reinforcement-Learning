## DPO 的数学细节

上一章还在调 PPO 的接口，这一章回到纸上。

DPO 的损失只有一行，但那一行是从一个约束优化问题解出来的。解的过程值得走一遍，因为后面所有变体都在改其中的某一步。知道每一步在做什么，看到新变体时就能判断它动了哪里。

### 从带约束的目标出发

起点和 PPO 完全一样。给定提示 $x$，希望策略在拿到高奖励的同时不要离参考模型太远。

$$
\max_{\pi}\ \mathbb{E}_{y\sim\pi(\cdot\mid x)}\left[r(x,y)\right] - \beta\,\mathrm{KL}\left(\pi(\cdot\mid x)\,\|\,\pi_{\text{ref}}(\cdot\mid x)\right)
$$

关键观察是，这个问题对每个 $x$ 可以分开解。不同提示之间没有耦合，$x$ 只是条件。所以固定一个 $x$，把策略看成一个在候选回答上的分布，问题就变成一个普通的带约束优化。

把期望和 KL 都展开。

$$
J(\pi) = \sum_{y}\pi(y\mid x)\,r(x,y) - \beta\sum_{y}\pi(y\mid x)\log\frac{\pi(y\mid x)}{\pi_{\text{ref}}(y\mid x)}
$$

约束是概率归一，$\sum_y \pi(y\mid x) = 1$。引入乘子 $\lambda$，写成拉格朗日函数。

$$
\mathcal{L}(\pi,\lambda) = \sum_{y}\pi(y\mid x)\left[r(x,y) - \beta\log\frac{\pi(y\mid x)}{\pi_{\text{ref}}(y\mid x)}\right] - \lambda\left(\sum_{y}\pi(y\mid x) - 1\right)
$$

对每个 $\pi(y\mid x)$ 求偏导，令其为零。

$$
r(x,y) - \beta\log\frac{\pi(y\mid x)}{\pi_{\text{ref}}(y\mid x)} - \beta - \lambda = 0
$$

整理出对数比。

$$
\log\frac{\pi(y\mid x)}{\pi_{\text{ref}}(y\mid x)} = \frac{r(x,y) - \lambda}{\beta} - 1
$$

两边取指数。

$$
\pi(y\mid x) = \pi_{\text{ref}}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right)\cdot\exp\left(-\frac{\lambda}{\beta} - 1\right)
$$

后面那一项与 $y$ 无关，可以并进归一化常数。

$$
\pi^*(y\mid x) = \frac{1}{Z(x)}\,\pi_{\text{ref}}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right),\qquad
Z(x) = \sum_{y}\pi_{\text{ref}}(y\mid x)\exp\left(\frac{r(x,y)}{\beta}\right)
$$

这就是最优策略的闭式解。它的形状很好读。参考策略提供基础的分布，奖励对每一项做指数加权。$\beta$ 控制加权的锐度，$\beta$ 越小，加权越极端，最优策略越集中在奖励最高的那一条上。$\beta$ 趋于零时，解退化成一个众数解，也就是把所有概率压到最好的那条回答上。

### 反解奖励

第二步是把奖励解出来。把上式取对数。

$$
\log\pi^*(y\mid x) = \log\pi_{\text{ref}}(y\mid x) + \frac{r(x,y)}{\beta} - \log Z(x)
$$

移项，乘 $\beta$。

$$
r(x,y) = \beta\log\frac{\pi^*(y\mid x)}{\pi_{\text{ref}}(y\mid x)} + \beta\log Z(x)
$$

这个式子说的是，奖励可以由策略和参考策略的比值表示，只差一个只依赖 $x$ 的常数项。

这一步是整个方法的关键。它把"学习一个奖励函数"换成了"学习一个策略"，两者在最优解处是等价的。奖励模型的参数化和策略的参数化，本来是两个问题，这里合成一个。

接下来代入偏好模型。偏好概率用 Bradley-Terry 假设，取决于两条回答的奖励差。

$$
P(y_w\succ y_l\mid x) = \sigma\left(r(x,y_w) - r(x,y_l)\right)
$$

把上面的反解代进差值里。

$$
r(x,y_w) - r(x,y_l) = \beta\log\frac{\pi^*(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)} - \beta\log\frac{\pi^*(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}
$$

$\beta\log Z(x)$ 在相减时消失了。这就是那个归一化常数不可算却不要紧的原因，它只依赖 $x$，在同一个提示内部比较时总是抵消。

用一个参数化的策略 $\pi_\theta$ 去近似最优策略，定义隐式奖励

$$
\hat{r}_\theta(x,y) = \beta\log\frac{\pi_\theta(y\mid x)}{\pi_{\text{ref}}(y\mid x)}
$$

就得到 DPO 的损失。

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(\hat{r}_\theta(x,y_w) - \hat{r}_\theta(x,y_l)\right)\right]
$$

整个方法到这里就完整了。没有奖励模型，没有在线采样，只有一个二分类损失。训练时把每条回答的对数概率按 token 加起来，减去参考模型的对数概率，再相减、过 sigmoid、取负对数。

有一个隐含的代价要说清。因为 $Z(x)$ 被消掉了，训练出的 $\hat r_\theta$ 只能在同一道题内部比较。拿它给不同题目的回答打分没有意义，不同题目的隐式奖励不在同一个尺度上。想把它当成通用的质量分用，必须先补一个难算的归一化项。这也是 DPO 不能直接当奖励模型用的原因。

### 推导里两个容易滑过去的点

第一个是那个归一化常数。$Z(x) = \sum_y \pi_{\text{ref}}(y\mid x)\exp(r(x,y)/\beta)$ 要对所有可能的回答求和，词表大一点就是天文数字，算不出来。

推导里它之所以不要紧，是因为只在同一道题内部比较。两道题之间比较，$Z$ 不同，隐式奖励就不在同一尺度上。有人把这个常数近似成一个和长度相关的项，确实能骗出一些可用的绝对分数，但这是工程近似，不是推导的结论。

第二个是整段对数概率怎么拆。书写上写的是 $\log\pi(y\mid x)$，实现里算的是 $\sum_t \log\pi(y_t\mid x,y_{<t})$。两者相等，前提是整段概率就是逐 token 条件概率的乘积。

这个拆法带来一个直接后果。一段两千 token 的回答，它的对数概率是一千个负数的和，量级比一段两百 token 的回答大十倍。所以在同一个对子里，长的那条无论对错，它的 $\Delta$ 绝对值都更大，梯度也更大。

这不是推导出错，是目标本身的性质。想让长短可比，就得在损失里显式归一化，后面会讲三种做法。

### 梯度在推什么

把这个损失对参数求一次导，能看清它在做什么。

记 $\Delta_\theta(y) = \log\pi_\theta(y\mid x) - \log\pi_{\text{ref}}(y\mid x)$，那么损失可以写成 $-\log\sigma\left(\beta(\Delta_w - \Delta_l)\right)$。

对 $\theta$ 求导，参考模型冻结，只有策略那一项有梯度。

$$
\nabla_\theta\mathcal{L} = -\beta\,\sigma\left(-\beta(\Delta_w - \Delta_l)\right)\left[\nabla_\theta\log\pi_\theta(y_w\mid x) - \nabla_\theta\log\pi_\theta(y_l\mid x)\right]
$$

这个式子有三层意思。

方向是提高 $y_w$ 的似然，降低 $y_l$ 的似然。这看起来像监督微调，但监督微调只有前半句。DPO 同时压低落选那条的概率，这一项是它和监督学习的分水岭。

权重是 $\sigma\left(-\beta(\Delta_w-\Delta_l)\right)$。它介于零和一之间，当模型已经把 $y_w$ 排在前面时，这个值接近零，梯度几乎不动。当模型排反了，这个值接近一，梯度最大。所以 DPO 自带难例挖掘，训到后期自动把注意力放到还没学会的对子上。

缩放来自 $\beta$。它同时放大梯度幅度，也改变权重的分布。这一点下一节细说。

还有一个细节值得指出。梯度里的对数概率是整段之和，$\nabla\log\pi_\theta(y\mid x) = \sum_t \nabla\log\pi_\theta(y_t\mid x,y_{<t})$。这意味着一条长回答的梯度幅度天然比短回答大。这就是 DPO 长度偏置的来源，它不在损失的形式里，在梯度的结构里。

和 PPO 比，DPO 的梯度很温和。PPO 有重要性采样比，比值可以很大，所以需要裁剪。DPO 没有比值，权重被 sigmoid 锁在零到一之间，单步更新幅度有上界。这解释了为什么 DPO 很少训练崩溃，也解释了为什么它学得慢。

把权重量出来看更清楚。取 $\beta$ 分别等于零点零一、零点一、零点五，对数概率差 $\Delta_w-\Delta_l$ 从负二到正十变化。

$\beta$ 等于零点零一时，权重从零点五零五到零点四七五，几乎是一条直线。模型把明显更好的排在前面，和把略差的排在前面，梯度差不多。

$\beta$ 等于零点一时，权重从零点五五降到零点二七，开始有区分。

$\beta$ 等于零点五时，权重从零点七三降到零点零一，差得越多，梯度越小，自动把注意力留给还没学会的对子。

所以 $\beta$ 小的时候，训练像是在均匀地推所有对子；$\beta$ 大的时候，训练像是在只推最难的那几个。前者稳但慢，后者快但容易在噪声上过拟合。

### 一个手算的例子

拿一对数据走一遍，把公式里的每个量都填上数。

设策略模型给被选中那条的整段对数概率是负二点零，给落选那条是负二点五。参考模型给的两条分别是负二点二和负二点三。

先算两个差值。被选中那条是负二点零减负二点二，等于正的零点二。落选那条是负二点五减负二点三，等于负的零点二。

相减得到零点四。这个数就是 $\Delta_w - \Delta_l$，也是隐式奖励差除以 $\beta$。

取 $\beta$ 等于零点一，sigmoid 的自变量是零点零四，偏好概率是零点五一，损失是零点六七三。训练第一步如果正好碰到这个数，说明模型几乎分不出两条回答的好坏，符合预期。

梯度前面的系数是 $\beta$ 乘零点四九，约等于零点零四九。这个系数会乘在“提高被选中那条、压低落选那条”的方向上。零点零四九很小，所以这一步的更新幅度很小。

同一对数据换成 $\beta$ 等于零点五，自变量变成零点二，概率零点五五，损失零点五九八，系数零点二五。大了五倍，学习快五倍，但稳定性差一些。

这个手算可以反复用来检查实现。把真实代码里打印的对数概率填进来，如果算出的损失和框架报的不一样，就是中间有一步写错了。比自己对着代码找半天快得多。

### β 的三个作用

$\beta$ 出现在两个位置，作用完全不同。

在闭式解里，$\beta$ 是 KL 的强度。$\beta$ 大，最优策略被拉在参考模型附近，改动保守。$\beta$ 小，最优策略可以离参考模型很远，趋近于只追奖励的解。这一层含义和 PPO 里的 $\beta$ 一样。

在损失里，$\beta$ 是 sigmoid 的斜率。$\beta$ 小的时候，$\beta(\Delta_w-\Delta_l)$ 被压扁，所有权重都靠近零点五，模型分不清"明显更好"和"略好一点"。$\beta$ 大的时候，sigmoid 迅速饱和，只有排错的对子还有梯度，训练变得像只看最难的那批样本。

两层作用会打架。想让模型大胆探索，就得调小 $\beta$，但调小之后梯度信号变弱，训练变慢。这个矛盾没有干净的解法，实践中的取值通常在零点零一到零点五之间，而且和模型大小、数据量都有关。数据里的偏好差距越小，$\beta$ 需要越大，否则 sigmoid 的自变量太小，等于没在学。

$\beta$ 还影响长度。隐式奖励是 $\beta$ 乘以对数概率比，对数概率比随长度线性增长。$\beta$ 越大，长回答和短回答的隐式奖励差距被放得越大。有些变体把整段对数概率改成平均对数概率，就是在去掉这个尺度依赖。

### β 怎么选

给一个可操作的流程，不靠直觉。

第一轮扫四个值，零点零一、零点零五、零点一、零点三。数据用同一份，步数用同一个上限，只改 $\beta$。

每个值看四个量。留出集上的偏好准确率。隐式奖励的差 $\hat r_w - \hat r_l$ 的均值。被选中那条的对数概率掉了多少。平均长度变了多少。

四个量的读法不一样。准确率上升是好的。奖励差上升但准确率不动，是过优化的前兆，说明模型在拉大差距而不是在学对。被选中那条的对数概率大掉，通常伴随语言能力退化，掉得过快就要停。长度明显上涨，说明 $\beta$ 把长度信号放大了。

一个常用的判据是把 $\beta$ 和奖励差一起看。$\beta$ 乘上奖励差，大致就是 sigmoid 的自变量。自变量落在二到四之间，梯度既不饱和也不太弱。太小就把 $\beta$ 调大，太大就调小。

这个判据比“调参经验”可靠，因为它不依赖数据规模，只依赖两个量的比值。

还有一条，$\beta$ 不要和长度上限一起调。两个都影响长度，同时改就分不清是谁在起作用。

### 和 PPO 的关系

两者优化的是同一个目标函数。差别在求解方式。

PPO 走的是迭代。每一步采样一批回答，用奖励模型打分，算优势，做一小步梯度上升。它需要奖励模型，因为优势要有一个数值来源。

DPO 走的是解析。它先用闭式解把奖励消掉，把问题变成一个只含策略的损失。所以它不需要奖励模型，也不需要采样。

从这个角度看，DPO 是"一步到位"，PPO 是"逐步逼近"。理论上两者的最优解相同，实践中差别很大，原因是数据。

PPO 的样本来自当前策略，训练和采样同步进行。模型变好，样本也跟着变好，它能看到自己刚刚生成的东西。

DPO 的样本是固定的。训练开始前采集好，训练过程中不会更新。训练到后期，策略已经偏离了数据分布，它还在拟合那些旧数据上的偏好。这个偏移会累积，表现为训练损失继续下降，实际效果却不再提升。

这也是迭代式做法出现的原因。跑一轮 DPO，用新策略重新采样、重新标注，再跑一轮。它把 DPO 往在线的方向推了一步，代价是回到需要采样的老路上。

还有一个差别在奖励的表达能力上。PPO 的奖励模型是一个独立的网络，可以学到数据里没有的模式。DPO 的奖励被绑在策略上，策略表达不出来的偏好，它学不到。

参考模型的选择同样要紧。它定义了什么叫做“不变”，选错了，后面的约束就落在错的地方。常见做法是用监督微调的终点，因为那一步之后模型的格式已经稳定。用基座模型做参考，KL 会一直很大，训练的大部分力气花在把格式拉回来。

有一个细节容易被忽略。$\pi_{\text{ref}}$ 和 $\pi_\theta$ 起点相同，所以训练第一步时 $\Delta_w$ 和 $\Delta_l$ 都是零，损失恰好是 $\log 2$。如果一开始损失就不是这个值，先查参考模型是不是加载对了。这条能省不少调试时间。

### 长度偏置的三种修法

前面推导里说过，长度偏置不在损失的形式里，在梯度的结构里。修法也因此分三层。

第一层是归一化。把整段对数概率除以长度，隐式奖励变成

$$
\hat r_\theta(x,y) = \frac{\beta}{|y|}\log\frac{\pi_\theta(y\mid x)}{\pi_{\text{ref}}(y\mid x)}
$$

分母是回答的 token 数。这样长短两条回答的梯度量级就接近了。代价是短回答的噪声被放大，一条只有十个 token 的回答，它的对数概率均值波动很大，容易被当成强信号。

第二层是加惩罚。不改变奖励的形式，直接在奖励差里减一个长度项。

$$
\Delta = \hat r_\theta(x,y_w) - \hat r_\theta(x,y_l) - \alpha\left(|y_w|-|y_l|\right)
$$

$\alpha$ 控制惩罚强度。这个做法最常见，因为它不动实现，只改一行。麻烦在于 $\alpha$ 和数据里的长度分布绑定，换一份数据要重调。

第三层是换目标。不用对数概率比做奖励，改用平均对数概率，再加一个目标间隔。

$$
\mathcal{L} = -\log\sigma\left(\frac{\beta}{|y_w|}\log\pi_\theta(y_w\mid x) - \frac{\beta}{|y_l|}\log\pi_\theta(y_l\mid x) - \gamma\right)
$$

$\gamma$ 是要求被选中那条领先的幅度。注意这个形式里参考模型消失了，不再需要加载第二份模型。代价是丢掉了 KL 约束，模型可以跑得很远。

三种修法都在改同一件事，把长度从奖励里剥出去。剥得越彻底，短回答上的噪声越明显。没有一个设置对所有数据都好，能做的只是把长度当成一个单独监控的指标，不指望损失函数替你解决。

### 参考模型加载错了会怎样

这一节看着像废话，实际上是最常见的一个错误。

训练第一步，策略和参考完全一样，所有 $\Delta$ 都是零，损失应该恰好是 $\log 2$，也就是零点六九三。如果第一步的损失是零，说明两条回答的分数差被算成了极大，几乎肯定是参考模型没加载对，或者被当成了策略本身在同时更新。

如果损失是 nan，先查概率是不是变成了零。长回答的整段对数概率是很多负数相加，在 fp16 下很容易下溢。用 log_softmax 而不是先 softmax 再取对数，是最直接的修法。

如果损失一直在零点六九三附近不动，两种可能。一是数据里的对子太简单，模型一开始就把被选中的排在前面；二是学习率太小，梯度根本推不动。看 $\beta$ 乘奖励差这个量就能分开，前者它很大，后者它很小。

把这三个现象写进监控，比看损失曲线管用。它们出现得早，而且指向明确。

### 几个变体各自动了哪一步

理解这几层关系之后，再看 IPO、KTO、ORPO 这些变体，就比较容易判断它们在补哪个缺口。

IPO 动的是偏好模型。它不用 sigmoid，改成平方损失，目标是让奖励差逼近一个固定间隔，而不是越大越好。这样即使数据里有噪声对子，模型也不会被推到极端。代价是间隔这个超参又需要调。

KTO 动的是数据形式。它不需要成对数据，只需要一条回答加一个“好”或“坏”的标签。好处是能直接用上大量单边反馈，比如线上的点赞点踩。坏处是丢掉了对子内部的相对信息，同一个提示下两条都不错时，KTO 分不出哪条更好。

ORPO 动的是流程。它把监督微调和偏好优化合成一步，在普通的交叉熵损失上加一个比值项。省掉了单独的参考模型和单独的训练阶段，工程上简单。代价是两个目标的权重需要配平，配不好会出现格式学会但偏好没学到。

| PPO | 提示，在线采样 | 需要 | 靠奖励里的长度项 | 工程复杂，采样贵 |
| DPO | 成对偏好 | 需要 | 梯度天然偏向长回答 | 离线，后期失效 |
| IPO | 成对偏好 | 不需要 | 同样偏长 | 间隔超参 |
| KTO | 单条加好坏标签 | 需要 | 同样偏长 | 丢掉对子内比较 |
| ORPO | 成对加示范 | 不需要 | 与交叉熵混在一起 | 两个目标要配平 |

看这张表的方法很简单。先问自己手上有什么数据，再问能付多少工程成本，最后才看论文里的分数。顺序反了，会选一个跑不起来的方案。

还有一个共同的盲区值得提。这些方法都在优化“被选中的比落选的好”，但没有一个在学“好到什么程度”。所以训完之后模型能排序，不能打分。想拿它做拒答阈值、做数据筛选、做候选重排，都需要额外一层校准。

### 实现上只要三个对数概率

抛开推导，DPO 的代码很短。每条样本需要三个量，策略模型对两条回答的对数概率，参考模型对两条回答的对数概率。四个数拼成损失。

```python
import torch
import torch.nn.functional as F

def seq_logprob(model, input_ids, labels, mask):
    # sum log p over response tokens only
    logits = model(input_ids).logits[:, :-1]
    logp = F.log_softmax(logits.float(), dim=-1)
    tok = logp.gather(-1, labels[:, 1:].unsqueeze(-1)).squeeze(-1)
    return (tok * mask[:, 1:]).sum(-1)


def dpo_loss(policy, ref, batch, beta=0.1):
    lw = seq_logprob(policy, batch["w_ids"], batch["w_lab"], batch["w_mask"])
    ll = seq_logprob(policy, batch["l_ids"], batch["l_lab"], batch["l_mask"])
    rw = seq_logprob(ref, batch["w_ids"], batch["w_lab"], batch["w_mask"])
    rl = seq_logprob(ref, batch["l_ids"], batch["l_lab"], batch["l_mask"])
    # reference is frozen, so these two rows need no grad
    margin = beta * ((lw - rw) - (ll - rl))
    return -F.logsigmoid(margin).mean()
```

三个实现细节。

一是错位。预测第 $t$ 个 token 用的是第 $t-1$ 个位置的输出，所以 logits 要去掉最后一个位置，标签要去掉第一个位置。这一步对不齐，损失也会降，但学的是“预测自己”，不是预测下一个词。

二是掩码。只在回答部分累加，题面部分不计。题面在两条回答里是相同的，计进去只会给两条加同一个常数，不影响差值，但会拖慢计算。

三是精度。整段对数概率是几百个负数的和，fp16 下容易下溢成负无穷。在 log_softmax 之前转 float32，是最省事的修法。

还有一件与代码无关但影响很大的事，批内要混合长短。如果一批里全是很长的对子，梯度量级很大；全是短的，梯度很小。按长度分桶再交错组批，训练会稳很多。

推导到这里，参数的含义都摊开了。但公式之外还有一半的功夫，在数据和验证器上。下一章讲可验证奖励的工程，那里没有偏好模型，所有问题都出在题目和判分上。
