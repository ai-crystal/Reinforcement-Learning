## 奖励模型训练实战

奖励模型的论文只有一页公式，实现却常常要几个月。问题几乎都不在损失函数上，在数据。

这一章讲训练奖励模型时的具体问题。偏好数据怎么来，长度偏置怎么处理，评估的天花板在哪里，哪些坑最常见。

### 偏好数据怎么来

一条偏好数据是一个问题加两段回答，标注哪个更好。

回答从哪来，决定了数据的性质。常见的来源有三种。

同模型不同温度。用待训练的策略模型，一条用低温采，一条用高温采。低温那条通常更稳，高温那条偶尔更精彩。这种数据直接对应训练时的分布，最贴合目标，缺点是两条回答的差距小，标注者难分。

不同模型。用强模型和弱模型各生成一条，强模型那条往往被选中。这种数据容易标，一致率高，缺点是差距太大，模型学到的判断很粗，分辨不出两个都不错时哪个更好。

人工改写。让标注者先写一条好回答，再让模型生成一条差的对照。质量可控，成本最高。

多数项目混着用。同分布的对子占多数，用来教模型分辨细微差别。差距明显的对子占少数，用来把方向定住。

### 一条偏好数据的完整生命周期

把一条数据从无到有用的过程拆开，能看出成本花在哪里。

第一步选提示。提示要覆盖部署时真实会遇到的问题，不是研究者觉得有意思的问题。一类常见的错是只用知识问答，结果奖励模型在写作、改写、多轮对话上打分完全无意义。提示的多样性比数量重要，同一道题的多条回答只能贡献一个方向的信号。

第二步生成候选。每道题生成两到四条，总条数控制在每题不超过四条。条数一多，标注成本线性上涨，而边际信息很快耗尽。生成时要把温度和长度都记录下来，后面分析偏置时全靠这些字段。

第三步粗筛。两条完全一样的去掉。长度差超过一倍的对子单独放。格式崩掉的、答非所问的去掉。这一步通常能删掉一两成，成本几乎为零，收益却不小。

第四步标注。一人标，一人抽检。抽检比例一到两成，发现一致率低于阈值就把那批退回去重标。

第五步后处理。把标平局的单独打标，把位置打散，把超长的截断。位置打散这件事必须做，而且要在划分数据集之前做，否则训练集里被选中的总在前，模型会学到位置。

第六步划分。按题划分，不按对划分。同一道题的不同对子必须落在同一侧。这一步错了，留出集准确率会虚高十几个点，而且错得很隐蔽。

一条数据走完这六步，成本大概是几毛到几块。看起来不多，但几万对堆起来就是一笔真金白银，而且返工的成本比首标高。所以指南和抽检要在扩量之前做好。

### 标注指南怎么写

指南写得粗，一致率就上不去，后面调损失函数都是白费。

一份能用的指南至少要回答五个问题。

什么叫更好。要给一个可操作的顺序，比如先看事实对不对，再看是否回答了问题，再看是否完整，最后才看表达。顺序不能乱，否则标注者会在“写得漂亮但答错”和“写得粗糙但答对”之间犹豫。

长度算不算优点。要明写，更长不等于更好，只有当多出来的内容提供了新信息时才算。这一条能直接抬高一致率，因为它把最常见的分歧点提前定死了。

客气算不算优点。同上面，明写不算。礼貌用语不计分，除非用户明确要求语气。

什么时候标平局。给一个比例上限，比如不超过一成五，同时给几个例子。不设上限，标注者会大量标平局来逃避判断。不设下限，平局信息就被浪费。

拒答怎么处理。安全的拒答优于不安全的回答，但无必要的拒答要扣分。这两件事要分开写，否则标注者会把所有拒答都当安全处理。

指南写完之后要跑一轮试标。抽五十对，三个人独立标，算两两一致率。低于七成，回去改指南，不要开始正式标。这一步看起来慢，实际上是最快的做法，因为它把返工提前了。

数据量不用很多，但要够杂。公开的经验是几万到十几万对能训出一个可用的奖励模型，继续加量的收益递减得很快，因为瓶颈在标注一致性而不是样本数。

标注一致性要单独测。抽一百对让两个标注者独立标，算一致率。如果低于七成，先修标注指南，不要急着扩量。指南里要把“更长”和“更好”分开写，把“更客气”和“更正确”分开写，这两条能提不少一致率。

平局不要扔。两条回答差不多好时，标注者会倾向随便选一个，这种数据带着随机噪声。更好的做法是允许标平局，训练时把分数差的目标设为零而不是正数。损失写成

$$
\mathcal{L}_{\text{tie}} = -\log\sigma\left(-\left|r_\phi(x,y_1)-r_\phi(x,y_2)\right|\right)
$$

两侧都拉，谁高谁低不重要，只要差距小。这样一条平局样本提供的信息是“这两条差不多”，而不是一个随机方向。

### 损失与实现细节

标准损失是 Bradley-Terry 的负对数似然。

$$
\mathcal{L}(\phi) = -\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right)\right]
$$

实现上有三个细节值得写清楚。

一是位置。分数取哪个 token 的隐藏状态，决定了模型看没看到整段回答。取最后一个非 padding token 是常规做法。取平均会混进 padding 的噪声，除非掩码写对。

二是成对。一对回答要过两次前向，显存是单条的两倍。批内可以共享问题部分的计算，但多数框架没做这个优化。

三是对称。被选和落选的顺序要在数据里打散。如果数据里被选中的总在前，模型会学到位置而不是内容。

```python
def bt_loss(r_w, r_l, margin=0.0, tie=None, beta=1.0):
    """r_w, r_l: scalar rewards, shape (batch,)."""
    diff = beta * (r_w - r_l - margin)
    loss = -logsigmoid(diff)
    if tie is not None:
        # ties pull the difference toward zero from both sides
        loss = torch.where(tie.bool(), -logsigmoid(diff.abs()), loss)
    return loss.mean()
```

`margin` 用来要求被选中的那条领先一定幅度，适合差距明显的数据。`tie` 处理平局。两个参数都不改变模型结构，只改目标的形状。

模型这边倒没有太多花样。常见做法是从 SFT 模型初始化，把最后的输出头换成一个标量。全参训练效果好但贵，LoRA 便宜且够用，差别主要体现在数据量小时 LoRA 更稳。

学习率要比预训练小两个量级左右。奖励模型很容易过拟合，几千步就能把训练集背下来。判断过拟合不看损失，看留出集准确率，它一旦平了就该停。

### 训练循环里的四个细节

损失只有一行，工程细节却有四处容易错。

```python
import torch

def rm_batch(pairs, tok, max_len=2048):
    # one pair becomes two rows: chosen first, rejected second
    rows = [p for pair in pairs for p in (pair[0], pair[1])]
    enc = tok(rows, padding=True, truncation=True,
              max_length=max_len, return_tensors="pt")
    # index of the last real token, used for scoring
    enc["last_idx"] = enc["attention_mask"].sum(-1) - 1
    return enc


def rm_loss(model, batch):
    out = model(input_ids=batch["input_ids"],
                attention_mask=batch["attention_mask"])
    idx = batch["last_idx"].view(-1, 1, 1)
    score = out.logits.gather(1, idx).squeeze(-1).squeeze(-1)
    s_w, s_l = score[0::2], score[1::2]
    return -torch.nn.functional.logsigmoid(s_w - s_l).mean()
```

第一个细节是打分位置。代码里用注意力掩码求和减一，而不是直接取最后一列。右填充时最后一列是 padding，取它会得到一个和内容无关的分数。这个错误很常见，后果是损失能降，但模型学不到东西。

第二个细节是填充方向。语言模型的隐藏状态受右侧上下文影响。要弄清楚自己用的分词器是哪种填充，再决定取哪个位置。带左填充的批次里，序列开头是填充，末尾才是真内容。

第三个细节是截断。回答超过最大长度时，从尾部截掉会把结论切掉，从头部截掉会把题面切掉。稳妥的做法是超长对子直接丢掉，不要硬截。丢掉的量要记进日志，超过一成说明最大长度设小了。

第四个细节是分数精度。两个分数的差可能只有零点零几，用半精度算，差值会被舍入成零，损失就是一个常数，梯度为零。把分数头单独转成 float32 算，是一个两行代码的修法，能避开很多莫名其妙的训练不动。

还有一件不属于实现但常被搞混的事，奖励模型是否冻结。它的参数要更新，但不应和策略共享任何参数。共享了，策略会通过改奖励模型来拿高分，而不是真的变好。

### 长度偏置

这是奖励模型最顽固的问题。

标注者偏好更详细、更完整的回答，而详细往往意味着更长。偏好数据里长回答被选中的比例偏高，奖励模型学到这一点，就开始给长回答高分。策略再优化这个奖励，回答会一路变长。

判断有没有偏置，做一个简单的回归。取留出集里的偏好对，用长度差预测哪个被选中，看准确率。随机是百分之五十。如果长度差单独就能到六十以上，说明数据里长度和偏好强相关，奖励模型几乎肯定会学到它。

处理方法有几种。

在数据层控制。构造对子时限制长度差，比如只保留长度相差百分之二十以内的对子。这会让数据变少，但去掉的正是最容易学错的部分。

在损失层惩罚。给分数加一个长度项，训完之后再减掉。

$$
\tilde{r}(x,y) = r_\phi(x,y) - \lambda\,|y|
$$

这个做法简单，但 $\lambda$ 要和策略训练时的长度分布匹配，换一个模型就得重调。

在打分时归一化。有的实现按长度做分箱，每个箱内单独标准化，再做比较。这等于承认长度是一个干扰变量，用统计手段把它压掉。

三种做法都不能根治。长度和有用性在真实数据里确实相关，完全去掉长度信号，也会去掉一部分真实的偏好。

### 把长度偏置量成一个数

前面说用长度差预测偏好，准确率过六十就说明有问题。这个检查可以做得更细。

做法是把每个对子的长度差和标注结果拿出来，拟合一个简单模型，看长度差单独能解释多少。如果长度差的系数为正且显著，偏置存在。再把“哪条更完整”这个人工标签加进去，看长度差的系数降不降。降了，说明长度只是完整的代理，偏置不严重。不降，说明长度自己在影响判断。

还有一项检查更直接。把同一道题的两条回答都截到相同长度，再让标注者重标一小批，看结果变不变。变了，说明长度确实在干扰。这一项成本高，但结论最硬。

两个数值得记住。长度差的单独准确率，和去掉长度后奖励模型的准确率。前者高出后者越多，偏置越重。修完之后两个数应该靠拢。如果修完发现整体准确率掉了很多，说明砍掉的不只是偏置，也砍掉了真实信息，系数调小一点重来。

长度偏置还会随着策略变化而漂。训练初期策略短，奖励模型的长回答偏好影响不大。训练后期策略长，这个偏好会自我强化。所以偏置检查不能只在训奖励模型时做一次，要跟着下游训练一起监控。

### 校准与评估的上限

奖励模型的输出只有相对意义。给所有回答的分数加十，偏好概率不变。这意味着它的绝对值不能直接当质量分用。

真要用绝对值，需要锚点。固定几条参考回答，把它们的分数记下来作为基准，之后的新分数都相对这个基准报。这样跨版本比较才有意义。

校准的另一层意思是分布匹配。训练时见过的分数区间，和上线后遇到的分数区间往往不同。策略优化之后会生成奖励模型没见过的回答，这些回答的分数可能整体偏高或偏低。监控分数的分布漂移，比监控平均分更有用。

评估的上限来自标注本身。两个标注者对同一对回答的一致率通常只有七成到八成。这意味着留出集上的准确率超过这个数，多半是过拟合或者数据泄漏，不是模型真的更懂人。

所以看到奖励模型在留出集上做到百分之八十五的准确率，第一反应应该是查数据，而不是庆祝。

评估还要看两件事。一是按问题划分训练和留出集，同一道题的不同回答不能跨集，否则模型学到的是记住题。二是构造对抗集，让策略专门生成一批想骗高分的回答，看奖励模型会不会给荒谬的高分。第二项比第一项更能预测上线后的表现。

### 分数漂移怎么监控

奖励模型上线之后，它的输入分布会一直变，因为策略在变。监控要盯三个量。

第一个是分数均值。它缓慢上升是正常的，因为策略在优化这个奖励。突然跳一大截，通常说明策略找到了一个新模式，值得看一眼那些高分回答。缓慢下降更危险，说明策略开始生成奖励模型不熟悉的回答，分数失去意义。

第二个是分数分布的宽度。标准差变得很小，说明策略把回答收敛到了一类，奖励模型已经分不出好坏。标准差变得很大，说明出现了一批极端样本。两种都要查。

第三个是固定锚点的分数。准备五十条固定的参考回答，每次评估都跑一遍。它们的真实质量没变，分数变了就是漂移。这个方法比看均值可靠，因为它把策略变化的影响隔离掉了。

监控频率跟着训练走，每天跑一次就够，不必每一步都算。发现漂移先判断是数据问题还是策略问题。策略问题靠调 KL 系数能缓解，数据问题只能重标。

### 不打分的奖励模型

前面的奖励模型输出一个标量。还有一类做法让奖励模型先写理由，再给分。

好处是能被检查。分数异常时，可以看它写的理由对不对，而不是对着一个数字猜。坏处是贵，要生成一段文字，速度比一次前向慢一个量级。训练时的打分频率很高，这条路的直接成本通常付不起。

常见的折中是训练时用标量模型，评估时用会写理由的模型。后者当审计工具，定期抽一批样本，看两者的分歧在哪。分歧集中的题目类型，就是标量模型最不可靠的地方。

还有一类是过程奖励模型，给推理链的每一步打分，而不是给整段回答一个分。它能缓解长链里的信用分配，代价是标注成本高。每一步的好坏要人来标，一条二十步的推理就是二十个标点。

公开的实践中，过程奖励在数学和多步推理上有效，但在通用对话上不一定。原因是很多对话里每一步都没有对错之分，硬要打分只会引入噪声。选哪一种，看任务里是不是真的存在“这一步走对了”这个判断。

### 常见的坑

按出现频率排，大概是这几个。

**问题泄漏**。同一道题的多条回答被分到训练集和测试集两边。留出集准确率虚高，上线就崩。

**标注者偏差集中**。整批数据由一个标注团队完成，他们的偏好会变成模型的偏好。换一批用户，效果差很多。

**只拿被选中的回答训练**。这退化成监督微调，丢掉了对比信息。奖励模型的价值就在于它知道什么更差。

**数据分布太窄**。只用一种任务的数据训练，奖励模型在别的任务上给出无意义的分数。策略一旦探索到那个区域，训练就会跑偏。

**精度问题**。分数用半精度算，差值很小的对子会被舍入成零，损失失去梯度。用 float32 算分数头，是一个便宜的修法。

**奖励标准化放在训练里**。如果每一批都对分数做标准化，模型会学到相对关系依赖批次，换批次就漂移。标准化应该放在评估和下游使用上，不放训练目标里。

还有两个不属于数据质量、但同样常见的坑。

**标注时间跨度太长**。一批数据拖了三个月，前一个月和后一个月的标准已经不一样了。指南没变，人的尺度变了。处理办法是每隔一段时间重标一小批早期的对子，看新旧结果差多少，差得多就把早期的数据权重调低。

**只测平均准确率**。奖励模型在整体上七成准确，可能在某一类题上只有五成。策略一旦往那类题上探索，就会得到一个反向的信号。所以准确率要按任务类型拆开报，每一类的量不少于一两百对。

这些坑有一个共同点。它们都不是算法问题，而是数据工程问题。修一个坑通常比换一个损失函数带来的提升大得多。
