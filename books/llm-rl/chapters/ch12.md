## 对齐的代价：谄媚、退化与多样性

第 11 章末尾说，多轮任务的评估比单轮复杂得多。在谈评估之前，先看一件更容易被跳过的事。

对齐训练不是只加不减。它一边提升模型在目标上的表现，一边拿走一些东西。拿走了什么，往往要等到上线之后才被发现。

### 对齐税

做完偏好训练的模型，经常在通用基准上比监督微调的版本差一点。数学题掉两三个点，代码能跑的比例下降，写故事时用词变得保守。这个现象有个名字，叫对齐税。

具体数字因项目而异，方向却相当稳定。原因有几层。

偏好数据偏向安全、礼貌、结构化的回答。模型为了提高奖励，会把输出分布往这个方向收窄。收窄的过程里，那些不常见但有创造力的表达被压掉。

奖励模型本身有偏，模型学会了讨好它，而不是学会变得更有用。

信用分配太粗。整段回答只有一个分数，一些本来正确的 token 也被连带惩罚。

KL 约束只是限制幅度，不改变方向。它让模型别走太远，走的方向仍然是奖励指的方向。

观测的办法不复杂。训练前后在同一个基准、同一个提示模板、同一个采样温度上各跑一遍，比较的不只是目标指标，还有几项与目标无关的通用能力。数学、代码、长文写作，各留一条。很多团队只盯目标指标，等上线才发现模型在别的地方变笨了。

模型越小，这一项越明显。七 B 级别的模型做一轮偏好训练，通用能力的损失往往大于百 B 级别。原因不难想，小模型的容量刚好够装下预训练学到的东西，对齐训练挤进来一部分，就得挤出去一部分。

还有一点容易被忽略。对齐税不是训练结束就固定的。上线之后继续用新数据做增量训练，每一轮都会再收窄一点。几轮下来，模型可能变得很听话，也很平庸。

### 谄媚

用户说错，模型跟着错。用户说我觉得答案是 B，模型立刻改口。用户语气强硬，模型放弃原来的判断。

这是偏好训练最稳定的副作用之一。

来源很清楚。偏好数据里，附和用户的回答更容易被选中。标注者是人，人也喜欢被认同。这不是标注者不认真，是比较这种形式本身的局限。它只记录哪个更让人舒服，不记录哪个更正确。

检测可以很简单。取一批有确定答案的题，在原问题后面加一句带错误主张的用户意见，看模型是否改口。

```python
def flip_rate(ask, judge, items, pressure):
    """Ask each question twice: plain, then with a wrong user claim."""
    flipped = 0
    for question, gold in items:
        first = ask(question)
        claim = wrong_claim(gold)
        second = ask(question + pressure.format(claim=claim))
        if judge(first, gold) and not judge(second, gold):
            flipped += 1
    return flipped / len(items)
```

改口率高，说明模型把顺从排在了正确前面。这个数字和普通测试集上的分数几乎无关，需要单独测。

它还会污染其他评测。用模型做裁判时，如果裁判模型也有谄媚倾向，它会偏爱那些与自己立场一致的回答。结果是评分看上去很稳定，其实是在重复自己的偏好。做自动评测前，先用同一批样本换一换选项顺序，看看分数会不会变。

处理办法是在数据里补。偏好数据里显式加入坚持正确答案的样本，让标注者看到模型顶住压力的回答并选中它。也可以用另一个模型扮演用户施加压力，构造对抗样本。代价是这会让模型变得更固执，在用户其实说对的时候也不肯改。这是一条权衡线，不是越硬越好。

### 多样性与能力的收窄

同一个问题采十次，答案几乎一样。这不是稳定，是坍缩。

强化学习会强化高概率的路径。奖励只看结果，不问路径，于是少数成功的路径被反复强化，其他路径的概率被压到很低。

坍缩的后果分场景。单次问答里影响不大，反正只取一个答案。需要搜索的任务里影响很大，测试时计算那条路线依赖多次采样，采样没有差异，投票和搜索就失效了。

一个可观察的指标是 pass@1 和 pass@k 的差。训练之后 pass@1 上升，pass@k 反而下降，说明模型把概率集中到了少数解法上。

比多样性更值得担心的是能力窄化。在数学题上做强化学习的模型，经常出现一种情况，训练集同分布的题做得很好，换个题型就退回到原来的水平。有观察认为这说明学到的是解题模板，不是推理能力。这个判断还没有定论，但至少提醒一件事，训练分布的设计比算法选择更影响迁移。

窄化和多样性坍缩常常同时发生，源头却是两件事。前者是数据分布太窄，后者是优化把分布压窄。诊断时要分开看，改法也不同。

策略的熵也在下降。它定义为

$$
H(\pi_\theta) = -\mathbb{E}_{x,\,y\sim\pi_\theta}\left[\log \pi_\theta(y\mid x)\right]
$$

训练初期缓慢下降，属于正常收敛。如果几步之内掉得很快，通常是学习率太大、批次太小，或者奖励过于单一。

缓解的手段有几个。在损失里加熵奖励，鼓励保持分布。混入一部分没做过强化学习的监督数据。评估时同时报 pass@1 和 pass@k。三种做法都会让训练变慢，换来的是模型不会过早只认一条路。

### 过度拒答

安全训练之后，模型开始对正常问题说我不能帮你做这个。

这类回答在安全测试集上是加分项，在日常使用里是减分项。用户问一句普通的医学常识，模型回一段免责声明，体验就坏了。

原因是安全数据的边界画得比实际需要宽。很多数据集按关键词标注，只要出现某类词就归为有害。模型学到的是提到某类词就拒绝，而不是判断意图。

检测要成对做。准备一组看起来敏感但实际无害的问题，再准备一组真正有害的问题，分别测拒答率。好的模型在第一组上拒答率低，在第二组上高。两组差距小，说明模型没有学会区分，只是在按词面躲避。

这一项检查在面向普通用户的产品里尤其重要。客服、教育、医疗问询，用户的问题里天然带很多敏感词，模型如果一见词就拒，可用性会掉得很快。

### 什么时候不该上强化学习

到这里可以给一个消极的判断标准。以下几种情况，先别上。

任务单一，格式固定，手上有几千条高质量示范。这种情况监督微调就够，强化学习带来的提升抵不过风险。

目标无法自动验证，也没有可靠的偏好数据。这时候强化学习优化的是一团噪声，训得越久偏得越远。

团队没有评估能力。强化学习会把模型带向任何地方，包括你没测过的地方。没有评估就没有方向。

预算只够跑一次。强化学习需要反复试错，一次跑完不调参，大概率得到一个比原来更差的模型。作为量级参考，公开配方里一轮完整的在线训练，采样消耗的算力常常是监督微调的数倍到数十倍，而且这部分算力花在生成上，不能复用。

这几条不是要劝人别做，而是让人先算清楚账。同样的预算，把示范数据做扎实，往往比硬上强化学习更划算。

反过来说，任务需要探索，模型自己生成的成功样本能带着它往前走，评估也跟得上，这套方法才值得投入。

这些代价多半不是算法选错，而是工程上没把每一步的职责分清。下一部从预训练、监督微调与强化学习各自的分工讲起。评测放到全书的最后一章，等工程细节都摊开了再谈，那时能说清楚每个指标在测什么。
