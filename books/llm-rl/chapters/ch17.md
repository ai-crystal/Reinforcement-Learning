## 可验证奖励的数据工程

算法定下来之后，同样一套 GRPO，两个人跑出来的结果能差十几个点。差别几乎都在数据上。

可验证奖励听起来很干净，答案对就一分，错就零分。但"答案对不对"这件事，取决于怎么抽取、怎么比对、题目本身难不难。这一章讲这几件事。

### 难度与课程

奖励只有零和一，一组回答全对或者全错时，组内没有区分度。

用 GRPO 的话说，优势是组内标准化的结果。

$$
A_i = \frac{r_i - \mathrm{mean}(r_{1:G})}{\mathrm{std}(r_{1:G}) + \epsilon}
$$

全对时分子全为零，全错时也一样，梯度也是零。这一批数据白采了。

所以题目要筛。做法是维护每道题的通过率估计 $\hat p$，采样时优先取 $\hat p$ 落在中间的那些。太简单的题，模型每次都做对，学不到东西。太难的题，模型一次都做不对，也学不到东西。

中间区间取多宽，取决于组大小。组大小是八时，如果单条通过率是零点九，一组全对的概率接近零点四十三；如果是零点五，全对的概率只有千分之四。所以通过率高的题要更多样本才能挤出信号，这也是筛题的价值。

### 要通过率准到多少

拿八条估计一个通过率，误差很大。二项分布的标准差是根号下 $p(1-p)/n$。$p$ 等于零点五、$n$ 等于八时，标准差是零点一七七，九成五的区间是正负零点三五。也就是说 4/8 和 6/8 在统计上分不出差别。

把组大小改成十六，标准差降到零点一二五。三十二条，零点零九。想做到正负零点零五，需要一百条。这个量级显然不能每题都采。

实际做法是分层。先用十六条粗估一遍，把题分进三桶，太简单、中间、太难。只有中间那桶值得进一步估，也只有它们会被反复采样。粗估用的样本只算一次，不重复花。

还有一件事要说清楚。全对的概率随通过率上升得非常快。$p$ 等于零点九、组大小八时，$0.9^8$ 约等于零点四三，将近一半的批次白采。组大小十六时，降到零点一九。三十二时，零点零三。所以把组大小抬高，不只是为了降低方差，也是为了少浪费批次。

反向的全错概率同理。$p$ 等于零点一的题，练得再久也没有信号，得从题库里移除，而不是加样本。

通过率从哪来。最省事的办法是先跑一遍，用当前模型对每题采若干条，统计正确率。这一遍的生成量不小，但可以在训练开始前一次性做完，之后每隔一段时间更新。

课程有两种排法。

按难度递增。先用通过率高的题让模型上手，格式稳定之后再换难题。好处是早期就有正样本，训练曲线好看。坏处是模型可能先学会一套只在简单题上有效的模板。

按通过率加权采样。不排序，每道题被抽到的概率和它离中间区的距离成反比。这更接近自适应，实现也简单。

两种做法都能用，第一种更好调。要注意的是难度会随训练变化，一开始很难的题，两周后可能变成简单题。课程表要跟着重算，不能一次定死。

### 难度估计怎么平滑

直接用观测到的通过率排序，会有两个问题。采样少的题估计不稳，排在最前或者最后。全是零和全是一的题，下一次还会被选中或者被永久丢弃。

做法是加一个先验。把每道题的通过率估计写成

$$
\hat p = \frac{c + \alpha}{n + 2\alpha}
$$

$c$ 是成功次数，$n$ 是采样次数，$\alpha$ 是一个小常数。它的作用是把估计拉向零点五，采样越少拉得越多。一条 0/8 的题，$\alpha$ 等于一时估成零点一，不是零。一条 1/2 的题估成零点五，而不是一半。

这个形式叫拉普拉斯平滑，好处是让采样少的题不会因为几次偶然就被钉死。代价是难题会被高估，所以 $\alpha$ 不能大，通常取零点五到一。

另一个细节是权重衰减。一道题上周的通过率是零点二，这周模型变强了，可能已经是零点六。如果把历史全部平均，会低估它。做法是给新观测更高权重，比如指数滑动，每轮乘零点八再加新值。

这套东西看起来是统计细节，但影响很直接。不加平滑，采样少的题会占满两端；不加衰减，课程会跟不上模型的变化。两者都不加，课程表两周后就失效了。

题目来源也要看。从竞赛题、教辅、合成题里各取一部分，难度分布和风格都不同。合成题好控难度，但容易不自然，模型学到的可能是合成模板。竞赛题质量高，数量少，很容易被模型记住。三类混着用，并按来源分别统计通过率，才能看出模型是真的变强了，还是在适应某一类题。

### 题库会过期

还有一个很实际的问题，题库会失效。同一批题跑两周，模型把答案背下来了，奖励全部满分，梯度归零。这不是模型变强，是数据用完了。

判断办法是看全对的比例。同一道题八条全对，说明它已经失效。一批题里失效的比例超过一半，就要换题。换题不必全部重造，加一成到两成新题就能把信号拉回来，因为新题会把曲线拉回中间区。

换题也有代价。新题的难度未经验证，可能整批都是零分，那一周的训练就白跑。所以新题要先小规模试跑一遍，确认通过率在合理区间，再放进主训练集。

### 答案抽取

模型输出一整段推理，程序要从中找到答案。这一步看着琐碎，是坏数据的主要来源之一。

办法是约定格式。推理过程放在固定标记之间，最后一行用固定前缀给出答案。训练时用提示模板强制这个格式，抽取时用正则找。

```python
import re

BOXED = re.compile(r"\\boxed\{([^{}]*)\}")
LAST_LINE = re.compile(r"####\s*([^\n]+)")

def extract(text):
    hits = BOXED.findall(text)
    if hits:
        return hits[-1].strip()
    m = LAST_LINE.search(text)
    if m:
        return m.group(1).strip()
    return None
```

三个细节。

取最后一个匹配，不取第一个。模型有时会在推理中途写一个临时的 boxed，最后再给最终答案。取第一个会大面积判错。

抽取失败必须单独统计。一个健康的训练集，抽取失败率应该在百分之一以下。如果到了百分之十，说明格式没训好，这时候奖励信号里有十分之一是假阴性，等于给正确回答发零分。这种噪声比随机噪声更糟，因为它系统性地惩罚了正确的行为。

模型的输出会被截断。达到最大长度时，答案可能还没写出来。这类样本要单独标记，不要混进错题里。

### 抽取器的六个坑

前面那段正则能用，但在真实数据上会碰到几种情况。

第一个是嵌套括号。模型写 $\boxed{\frac{1}{2}}$，用不匹配括号的正则只能抽到一部分，得到一个半截表达式。修法是写一个手动的括号计数，而不是靠正则。

第二个是转义与双反斜杠。模型有的写 \boxed，有的写双反斜杠，从 JSON 里读出来的字符串又会多一层转义。抽取前先统一处理一层反斜杠。

第三个是多次出现。推理中途出现一个临时答案，最后又给一个。取最后一个比自己猜哪个是最终答案可靠。

第四个是符号变体。乘号写成星号或叉号，除号写成斜杠，百分号被丢。这些在同义化简之前要先把符号映射到统一形式。

第五个是单位。答案写 12 cm，标准答案是 12。要么把单位从两边都去掉，要么把单位当成答案的一部分并在题面里约定。两种都行，混着来就不行。

第六个是全角半角。中文标点里的括号、逗号、小数点，和半角不是同一个字符。统一做一次归一化。

```python
def take_boxed(text):
    # scan for boxed answers and match braces by counting
    out = None
    key = "boxed{"
    i = text.find(key)
    while i >= 0:
        j, depth = i + len(key), 1
        while j < len(text) and depth:
            if text[j] == "{":
                depth += 1
            elif text[j] == "}":
                depth -= 1
            j += 1
        if depth == 0:
            out = text[i + len(key):j - 1]
        i = text.find(key, j)
    return out
```

这段代码比正则长，但它能处理嵌套。一个抽取器的好坏，不看它能不能处理正常样本，看它在畸形样本上会不会默默返回空值。返回空值最危险，因为它会被当成答错，模型因此受到惩罚。

### 验证器

抽出答案之后要判断它和标准答案是否等价。字符串直接比会错得很离谱。

分数要通分，小数和分数要能互认。表达式要能化简，$2\sqrt{2}$ 和 $\sqrt{8}$ 是同一个数。单位要能省略，空格和标点要忽略。集合类的答案要能与顺序无关。

```python
from sympy import simplify, sympify
from sympy.parsing.sympy_parser import parse_expr

def canon(s):
    return s.strip().replace(" ", "").replace(",", "").lower()

def equal(pred, gold, tol=1e-6):
    if pred is None:
        return False
    if canon(pred) == canon(gold):
        return True
    try:
        return abs(float(sympify(pred) - sympify(gold))) < tol
    except Exception:
        pass
    try:
        return simplify(parse_expr(pred) - parse_expr(gold)) == 0
    except Exception:
        return False
```

这段代码不算完美，但覆盖了大部分情况。要注意的是 `sympify` 会执行表达式，训练数据来自不可信的模型输出，做大规模训练时应该放在受限的解释器里跑，或者用符号解析器而不是求值器。

验证器要往两个方向测。拿一批标准答案，故意改写成等价形式，看是否判对。再拿一批错误答案，看是否判错。两个测试集都要有，只测一边会调出偏保守或者偏宽松的验证器。

偏保守的后果是正确回答被判错，模型学到的是别写复杂表达式。偏宽松的后果是错误回答被判对，模型学会的是凑形式。后者的破坏更大，因为它会直接导致奖励黑客。

还有一类任务没有标准答案，只有测试用例。这类任务的验证器就是跑代码，风险也更高，因为代码可以读环境、可以改文件。训练时的沙箱必须真的隔离，网络、文件系统、进程都要限制。这不是安全讲究，是防止几千个进程同时把机器跑死。

### 验证器分四层

不同任务的验证难度差很远，可以按四层排。

第一层是字符串比对。去空格、改大小写、统一标点，然后比。便宜、确定，但只能处理单选、数值、固定格式的答案。它最大的毛病是把等价形式判错。

第二层是数值比对。转成浮点数，带容差比。分数、小数、百分号、科学计数法在专用处理器里走过一遍。容差要跟着量级变，绝对容差在 1.2 和 12000 这两种答案上不可能同时合适，通常用相对容差加一个很小的绝对下限。

第三层是符号比对。用符号计算做差再化简，能处理根号、分式、集合、不等式。它很准，但慢，而且对输入格式敏感。符号表达式里混进中文单位或者多余空格，化简就会失败，回退到判错。

第四层是模型判。两段文字意思相同但表述不同，只有模型能判。它最贵、最不准、也最不可复现。用的时候要固定模型版本、固定提示、固定温度为零，并且定期用人工样本校准。

:::

| 层次 | 典型任务 | 代价 | 主要误判方向 |

| 字符串 | 单选、固定格式 | 几乎为零 | 把等价形式判错 |

一个实用的原则是从低层往上走，低层能判就不上高层。这样便宜、确定、可复现。只有当低层全部不确定时，才调模型，并且把调用过的样本单独记一笔，后面人工抽查。

还有一条经验。验证器本身的准确率要单独测，不要假设它对。拿两百道题，人工标一遍真值，再看验证器判得对不对。这个数字是训练信号的天花板，它低于九成，后面的奖励设计再好也白搭。

### 测试用例

代码任务的验证器是单元测试。这里的工程问题更多。

测试要分公开和隐藏。公开的给模型看，帮它理解要求。隐藏的用来判分，防止它针对测试写死代码。

测试要覆盖边界。空输入、超长输入、重复元素、负数、越界。模型写的代码经常在主路径上正确，边界上崩溃。

测试不能 flaky。涉及随机、时间、浮点的用例要做确定性处理，否则同一份代码跑两次结果不同，奖励就不稳定。发现 flaky 用例要立刻删掉，不要指望用重试掩盖。

测试不能太少。三个用例的题，模型写个特判就能过。一道题至少要有覆盖主要分支的若干用例，具体数目看任务复杂度。

测试也不能太严。要求输出格式一字不差，会把正确但格式略有差异的解判错。除非格式本身是任务的一部分，否则应该放宽。

对不稳定的用例，有一个便宜的发现办法。把同一份参考正确代码跑一百次，任何一次结果不同就标为可疑。这一轮能筛掉大部分依赖时间、随机数、并发调度的用例。再用一份故意写错的代码跑一遍，如果它能过，说明用例太弱。

用例的验收也要人看。自动生成的测试往往只覆盖 happy path，边界值全缺。抽十道题人工读用例，能看出生成器的通病。这个成本很低，收益比调奖励函数大。

### 长度、去重与污染

长度要控。奖励只看对错时，模型有明确的动机写得更长，因为长推理碰巧对的概率更高。这是有代价的，推理成本上去，延迟变长，可读性下降。

处理办法是在奖励里减一个长度项，或者按长度分桶统计正确率。后者的信息量更大，能看出模型是不是只在长回答上正确。

去重容易被忽略。题库来自多个来源，同一道题换个数字、换个说法就会出现好几次。近似重复的题会让模型过度拟合那个题型，也会让通过率估计失真。做法是用 n-gram 或 MinHash 做近似去重，相似度超过阈值只留一条。

污染检查是另一回事。训练题库里如果混进了评测集的题，评测分数就不可信。检查办法是拿训练题和评测题做片段匹配，命中的删掉。还要注意改写的题，题面不同但解法完全一样，这类只能靠人工抽查。

### 污染检查的三种手段

第一种是片段匹配。把两道题分别切成固定长度的字符片段，算重合比例。阈值定得低一点，宁可多删。它便宜、能跑全量，能抓到直接抄和轻微改写的题。抓不到的是完全重写题面但保留解答的题。

第二种是语义近似。用句向量算相似度，找那些字面不同但意思一样的题。它能抓到改写，但会误伤同一考点的不同变体，而那类变体恰恰是训练需要的。所以它只能用来辅助人工抽查，不建议全自动删。

第三种是按时间切分。评测集只收录模型训练数据截止之后发布的题。这是最硬的一种隔离，不依赖任何算法。代价是时间一长，新题也会被模型见过，需要持续更新。

还有一种情况容易被漏，答案泄漏而不是题面泄漏。题面没重叠，但标准答案的一段话被写进了某个网页，模型在预训练时读过。这类只能从答案侧查，把标准答案切成片段去搜训练语料。

检查要定期重跑，不能只在上线前跑一次。训练语料会更新，评测集会扩充，任何一边变了都要重查。把检查脚本和数据集版本一起存下来，出问题时能回到某个已知干净的状态。
