## 一个 token 就是一步动作

把语言模型放进强化学习的框架，只需要做一个替换。状态是已经生成的文本，动作是下一个词，策略就是模型本身。

这个替换看起来简单，但它改变了很多东西的尺度。Atari（Atari 2600 游戏，2013 年起成为基准）的动作只有十几个，词表有十几万。一局游戏几百步，一段回答几千个 token。奖励在游戏里每一步都有，在语言里通常只有一个，出现在最后。

这一章把这些差别摊开，为后面几章的算法做准备。

### 状态、动作、奖励

给定一个问题 $x$，模型逐字生成回答 $y=(y_1,\dots,y_T)$。第 $t$ 步的状态是 $(x,y_{<t})$，动作是 $y_t$，策略是

$$
\pi_\theta(y_t\mid x,y_{<t})
$$

这就是一个自回归的策略。动作空间是整个词表，每一步都在这个空间上给一个分布。

奖励通常是整段回答的分数 $R(x,y)$，在生成结束时才给出。这一条和棋盘游戏很像，中间没有反馈，只有终局评价。

稀疏奖励带来的问题前面反复提到过，这里是它最极端的形态。一段回答可能有几百个 token，只有一个标量告诉它整体好不好，哪些 token 该负责，完全没有信息。

### 动作空间有多大

先说动作。词表的大小由分词器决定，常见的中文模型在五万到十五万之间。分词用的是 BPE（byte pair encoding，字节对编码）一类的算法，把常见字符串合成一个 token，罕见字符串拆成几段。

这带来一个反直觉的后果，动作不是字，也不是词，而是统计意义上的高频片段。英文的常用词往往是一个 token，生僻词被切成两三段。中文的一个字通常占一到两个 token。数字最麻烦，“1234”可能被切成“12”和“34”，模型要做一位数的加法，就得跨 token 协调。这解释了早期模型为什么在算术上明显弱于在其他任务上的表现，也解释了后来的推理模型为什么习惯把数字拆开、一位一位地写。

动作空间大还有两个副作用。一是输出分布有十几万维，softmax 要在整个词表上归一化，采样一个 token 和算它的对数概率都不便宜。二是很多动作在语义上等价，同一个意思有十来种说法，模型选哪个都不影响回答好坏，但算法会把它们当成完全不同的动作。同一段“好回答”可能对应几十条不同的 token 序列，优势估计因此带上了一层额外的噪声。

### 长度是策略自己的决定

Atari 的一局多久，由游戏规则决定。语言模型的回答多长，由模型自己决定，因为结束符也在词表里，生成它就是一个动作。

这让长度变成了一个内生变量。和游戏相比，其它要素都还算稳定，只有长度会随训练变化，而且变化的幅度往往很大。如果奖励和长度存在任何正相关，哪怕很微弱，优化压力都会把它放大。实践中常见的情况是，训练几百步之后平均长度翻了一倍，人工评分却没有同步提高。

有一个便宜的自查办法。把训练前后的平均长度和平均奖励画在同一张图上，两条曲线一起往上走，就要怀疑分数是长度带来的。这时候该去检查奖励模型有没有长度偏置，而不是继续加训练步数。

### 一个数字例子

把尺度感算一遍，会明白后面的实现为什么要那样写。

假设提示有 200 个 token，回答有 400 个 token。模型对每个 token 的平均对数概率是 -0.05，整段的对数概率就是 -20。这个数看着不大，但取指数之后是十的负九次方量级，序列概率本身就是这么小，不必惊讶。

现在假设策略更新之后，平均对数概率从 -0.05 变成 -0.04，也就是每个 token 只自信了一点点。整段对数概率从 -20 变成 -16，差 4 个自然对数单位。整段的重要性采样比是 exp(4)，约等于 55。

这就是整段比值不能用的原因。逐 token 看，比值是 exp(0.01)，约 1.01，完全在裁剪区间里。整段看，同样的更新让比值跳到 55 倍，裁剪会把它压平，梯度信息全丢。长度越长，这个放大越夸张，400 个 token 是 55 倍，800 个 token 就是 3000 倍。

所以 PPO 里那个比值一定是逐 token 算的，最后再对 token 求平均。这不是实现上的方便，是数值上唯一可行的做法。

### 为什么不能直接套 Q 学习

第一个障碍是动作空间。十几万个候选词，每一步都要算 Q 值再取最大，代价和直接用策略采样差不多，但没有额外好处。而且语言的动作是离散的符号，相邻的词之间没有连续的“梯度”可以利用。

第二个障碍是状态空间。文本的状态是无限且不断增长的，任何一句话都可能是新的。价值函数不可能覆盖，只能靠泛化。

第三个障碍是奖励的粒度。整段回答一个分数，拆到每个 token 上是没有定义的。有人试过用 token 级的奖励模型，但那需要额外的标注，而且容易引入噪声。

所以在语言模型上，主流做法是策略梯度这一类方法，直接用整段（或者整段加 KL）的奖励去调整策略。价值方法在这一块基本退场。

### 为什么不干脆用监督学习

一个很自然的问题。既然已经有模型能写出好回答，为什么不把好回答收集起来做监督微调，非要用强化学习。

监督微调教的是“应该输出什么”。它告诉模型，在这个位置下一个 token 是这一个。它不会告诉模型“你刚才那个想法是错的”，因为数据里只有正确答案，没有错误的分支。学到的是一层很窄的映射，只在和训练数据相似的语境里有效。

强化学习教的是“哪种做法能拿到奖励”。它允许模型先犯错，再从对比里看出哪条路更好。这个区别在需要搜索的任务上很关键。一道数学题可能有五六种解法，数据里只记录了一种，监督微调只会强化那一种。如果模型自己采样出了另一种也对的解法，强化学习会把它的概率也提上去。

代价是方差。监督微调的梯度方向是确定的，强化学习的梯度是从采样里估出来的，同一个问题两次采样可能给出相反的方向。后面所有的工程细节，裁剪、基线、组内归一化，都是在和这个方差搏斗。

### 把整段回答当成一个动作

还有一种更粗的看法。把一整段回答当作一个巨型动作，忽略中间的 token，问题就退化成一个只有一步的赌博机。

这个看法不是玩笑，它在工程上真实存在。拒绝采样、最佳采样、多数投票，本质上都是在这个赌博机上做事。生成一堆样本，按分数挑一个或几个，用它们做微调或直接返回。整套流程里根本没有逐 token 的信用分配，也没有价值函数。

它能在一定范围内工作，是因为任务本身对“过程”不敏感。一个答案对了就是对了，怎么推出来的不重要。但它有明显的天花板。一是样本利用率低，一大半计算花在没被选中的回答上。二是没法区分“碰巧对”和“真会”，两者拿到同样的奖励。三是动作空间是词表的所有排列组合，想直接学到“哪种回答好”几乎不可能，只能靠筛选。

真正的策略梯度把粒度落到了 token。它承认中间过程值得区分，代价是信用分配变得困难。后面几章的算法，基本都是在这个尺度上做取舍。

### 状态分布会跟着策略漂移

在 Atari 里，状态分布也随策略变化，但变化是间接的，策略换了动作，环境才给出不同的状态。在语言里，状态直接由模型自己写出来，变化是直接的。

这带来一个监督学习里不存在的现象。训练开始时模型写的推理是短的、散的，日志里记录的状态都是这种。等模型学会了写长推理，它看到的状态就变成了长的、结构化的，而这类状态在早期数据里几乎没有。策略改进之后，它面对的问题分布变了。

后果是，用早期策略采的样本去更新后期的策略，偏差会很大。重要性采样比就是用来修正这个偏差的，但它只在分布相差不远时可靠。差得太远，比值会很大或者很小，方差爆炸。裁剪限制了比值，也就限制了“能用多旧的数据”。

所以在线训练里有一个隐含的要求，每一轮的数据要尽快用完。攒着不用，下一轮策略一变，数据就过期了。很多实现会在一批 rollout 上做几轮更新，轮数不能多，一般一到四轮，原因就在这里。

### 训练日志里的五个数

实际训练时，屏幕上滚动的指标不多，但五个数最能说明问题。

奖励均值。它应该缓慢上升，然后在某个水平上平台。上升很快往往是刷分的信号，尤其是长度同时在涨的时候。

KL。新旧策略的距离。它随训练上升，应当被控制在一个区间里。突然跳一个数量级，说明这一批更新出了问题。

裁剪比例。被裁掉的那些 token 占比。这个数在一成到三成之间算正常。接近一半说明单步更新太大，学习率或者轮数要降。

熵。策略的随机程度。它应该缓慢下降。下降太快意味着模型变得过于确定，探索停止。不降反升，说明策略在发散。

回答长度。它是最容易被忽略、也最能暴露问题的一个。奖励涨、长度涨、人工评分不涨，这是奖励黑客的典型形状。

这五个数之间的关系比单个数的绝对值重要。只看奖励，很容易被一个正在刷分的模型骗过去。

### KL 约束为什么必要

RLHF（reinforcement learning from human feedback，人类反馈强化学习）的目标函数通常长这样。

$$
J(\theta) = \mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta}\left[R(x,y) - \beta\,\mathrm{KL}\left(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\text{ref}}(\cdot\mid x)\right)\right]
$$

第二项把新模型拉向一个参考模型，通常是微调之后的版本。

这一项不是为了稳定训练才加的，它有实际作用。奖励模型只是一个近似的评价者，它有自己的偏好和漏洞。如果完全放任策略去最大化奖励，模型会找到奖励模型的弱点，生成一些在奖励模型看来分很高、在人看来很怪的回答。

KL 约束限制了偏离的幅度，让模型在“讨好奖励模型”和“保持原来的语言能力”之间保持平衡。$\beta$ 越大，越保守。

这里还有一个容易混淆的点。KL 是在整段序列上算的，逐 token 的对数比求和。长度越长，这个和越大，惩罚也越重。所以有人用逐 token 平均的 KL，有人用求和的 KL 再除以长度，两者对 $\beta$ 的敏感度不同。换实现的时候如果只照搬 $\beta$ 的数值，效果会差很远。

### 奖励的三种粒度

奖励可以给在三个层次上，每个层次对应一套不同的代价。

整段奖励最常见。一整段回答一个标量，简单、便宜、不需要额外标注。缺点是信用分配没有信息，模型只知道“这整段不错”，不知道是哪几句起了作用。

分段奖励把回答切成若干段，每段一个分数。切法可以是按推理步骤，按段落，按代码的函数。这种做法需要一个过程奖励模型（process reward model，PRM），它本身要训练，要标注，而且会在中间环节引入新的偏差。

token 级奖励最细，也最贵。标注者要指出具体哪个词用错了，成本高，一致性差。有人用奖励模型对每个前缀打分来代替，但那等于把一个整段评分器当成逐步评分器用，噪声会被放大。

这三种粒度不是越细越好。细粒度奖励给了更准的信用分配，代价是更多的标注、更多的模型、更多可以被钻空子的地方。第十章会看到，过程奖励模型自己也会被刷分，模型学会写出“每一步看起来都对”的推理，最后答案却是错的。

### 环境在哪里

Atari 有一个真实的环境，动作会改变世界，下一帧的状态由物理规则和随机性共同决定。语言模型没有这个世界。把 token 拼到上下文末尾，就是全部的“转移”，确定、无随机、无隐藏状态。

这个差别省掉了不少东西。不需要环境模型，不需要折扣因子，回报就是终局分数，折扣取一。也不需要考虑状态估计，因为状态就是文本本身，模型看到的和训练时记录的完全一致。

但“探索”的含义变了。Atari 的探索是试着按不同的键，看世界怎么反应，反馈是因果的、即时的。语言的探索是试着用不同的说法、不同的解法，反馈只来自最后的评分。哪一步走对了，哪一步是多余的，环境不会告诉模型。

还有一处不对称值得记住。Atari 的状态是给定的，语言的状态包含模型自己生成的内容。模型一旦写出一个错误的中间结论，后面所有推理都建立在这个错误上，而且它很难回头。这个现象在长推理里非常明显，也是后面要讨论“回头检查”这种行为的动机。

### 提示词算不算状态的一部分

算。状态是“提示加已生成的文本”，不是只有已生成的部分。这听起来是细节，实际影响很多实现。

第一，同一个回答配不同的提示，奖励可能完全不同。“解释一下熵”和“用一句话解释熵”是两个任务，回答长度和风格都应该不同。偏好数据里如果只存了回答不存提示，数据就没法用。

第二，一个批次里的提示长度参差不齐。短的一百个 token，长的一千个。为了拼成矩阵，短的要在左侧或右侧补齐，补齐的位置必须屏蔽掉，不然模型会把填充符当成内容学进去。

第三，提示是给定的，模型不为它负责。这也是后面“只对回答算损失”那条规则的根据，第三章会再提一次。

多轮任务里这件事更绕。工具返回的结果也是状态的一部分，但它不是模型生成的，不应该算进策略的对数概率里。如果算进去，模型会因为“没有把搜索结果写得更像”而被惩罚，方向就错了。

### 基线为什么要减

策略梯度里有一个反复出现的技巧，减基线。它不改变期望，只改变方差，但在语言模型上效果很明显。

举个具体情形。两道题，一道很容易，模型答对拿到奖励 1；一道很难，模型答错拿到奖励 0。如果不减基线，第一道题的每个 token 都被抬高，第二道题的每个 token 都被压低。问题是，第二道题里可能有一大半 token 写得很好，只是最后一步算错，它们也被一起压低了。

减掉基线之后，第一道题的优势变成一个小的正数，第二道题变成一个小的负数，幅度取决于基线定得多准。基线越接近真实期望，正负号保留而幅度变小，噪声也就小了。

PPO 用价值网络估基线，GRPO 用组内平均估基线。两种做法的区别只是估计方式，目的是同一个。这也解释了为什么 GRPO 去掉价值网络之后还能工作，它并没有去掉基线，只是换了一个更粗糙的估计。

### 和 Atari 的对照

把两边的要素摆在一起看，会清楚很多。

状态。Atari 是像素帧，固定大小，信息完整。语言是文本，长度可变，且包含模型自己生成的内容。

动作。Atari 是十几个按键。语言是十几万个 token，而且很多 token 在语义上等价。

奖励。Atari 每步都有分。语言通常只有一个终局分数，而且这个分数本身是另一个模型给的，有噪声。

回合长度。Atari 几百到几千帧。语言几十到几千个 token，长度本身还会被策略影响。

最后一条值得单独说。模型可以选择什么时候停止生成，这本身就是一个动作。如果奖励与长度正相关，模型会学会写得更长，哪怕内容没有变好。这个现象在 RLHF 里非常常见，第十章会详细讲。

### 一个容易忽略的细节

语言模型的策略是**自回归**的，每个 token 的条件依赖于之前所有 token。这意味着策略的分布在整段序列上是一个巨大的联合分布，而我们实际优化的是逐 token 的条件分布。

在计算概率时，整段回答的对数概率是各个 token 对数概率之和。

$$
\log\pi_\theta(y\mid x) = \sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t})
$$

这个分解在后面计算重要性采样比、KL 散度时都会用到。它也是“逐 token 处理”这种实现方式的依据。

分解带来一个实现上的便利，也带来一个概念上的陷阱。

便利是，整段的对数概率可以边生成边累加，不需要等回答生成完再回头算。生成的每一步顺手把对数概率存下来，后面算比值、算 KL 都直接用这个数组。几乎所有训练框架都是这么做的，存下来的东西一般叫旧对数概率，命名上带一个 old。

陷阱是，逐 token 的对数概率加起来才有意义，单独看某一个 token 的对数概率说明不了什么。有人看到某一步的对数概率是 -0.01，就说模型“很确定这一步”，这在局部是对的，但整段好不好由所有步骤共同决定。一个 token 的 -8 就能把前面几十个 -0.01 全部抵消。

还有一个细节和分词有关。同一句话如果分词方式不同，token 数会不同，对数概率之和也会不同。所以跨模型比较对数概率没有意义，甚至同一个模型换一版分词器也不能比。后面讲 DPO 的长度偏置时，这个细节是关键。

### 这一部要解决的问题

把生成看成决策之后，接下来的问题很自然：奖励从哪来？

如果每一步都有明确的对错，比如数学题的答案，事情就简单。但大多数任务没有标准答案，只有“这个回答比那个好”这样的相对判断。下一章讲怎么把这种比较变成一个可以优化的分数。

在那之前，先记住这一章立下的三个坐标。状态是文本，动作是 token，奖励是终局的一个标量。后面几章所有的算法改动，都没有跳出这个框架。差别只在于奖励从哪里来，优势怎么估，约束加在哪里。
