## 一个 token 就是一步动作

把语言模型放进强化学习的框架，只需要做一个替换。状态是已经生成的文本，动作是下一个词，策略就是模型本身。

这个替换看起来简单，但它改变了很多东西的尺度。Atari 的动作只有十几个，词表有十几万。一局游戏几百步，一段回答几千个 token。奖励在游戏里每一步都有，在语言里通常只有一个，出现在最后。

这一章把这些差别摊开，为后面几章的算法做准备。

### 状态、动作、奖励

给定一个问题 $x$，模型逐字生成回答 $y=(y_1,\dots,y_T)$。第 $t$ 步的状态是 $(x,y_{<t})$，动作是 $y_t$，策略是

$$
\pi_\theta(y_t\mid x,y_{<t})
$$

这就是一个自回归的策略。动作空间是整个词表，每一步都在这个空间上给一个分布。

奖励通常是整段回答的分数 $R(x,y)$，在生成结束时才给出。这一条和棋盘游戏很像，中间没有反馈，只有终局评价。

稀疏奖励带来的问题前面反复提到过，这里是它最极端的形态。一段回答可能有几百个 token，只有一个标量告诉它整体好不好，哪些 token 该负责，完全没有信息。

### 为什么不能直接套 Q 学习

第一个障碍是动作空间。十几万个候选词，每一步都要算 Q 值再取最大，代价和直接用策略采样差不多，但没有额外好处。而且语言的动作是离散的符号，相邻的词之间没有连续的“梯度”可以利用。

第二个障碍是状态空间。文本的状态是无限且不断增长的，任何一句话都可能是新的。价值函数不可能覆盖，只能靠泛化。

第三个障碍是奖励的粒度。整段回答一个分数，拆到每个 token 上是没有定义的。有人试过用 token 级的奖励模型，但那需要额外的标注，而且容易引入噪声。

所以在语言模型上，主流做法是策略梯度这一类方法，直接用整段（或者整段加 KL）的奖励去调整策略。价值方法在这一块基本退场。

### KL 约束为什么必要

RLHF 的目标函数通常长这样。

$$
J(\theta) = \mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta}\left[R(x,y) - \beta\,\mathrm{KL}\left(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\text{ref}}(\cdot\mid x)\right)\right]
$$

第二项把新模型拉向一个参考模型，通常是微调之后的版本。

这一项不是为了稳定训练才加的，它有实际作用。奖励模型只是一个近似的评价者，它有自己的偏好和漏洞。如果完全放任策略去最大化奖励，模型会找到奖励模型的弱点，生成一些在奖励模型看来分很高、在人看来很怪的回答。

KL 约束限制了偏离的幅度，让模型在“讨好奖励模型”和“保持原来的语言能力”之间保持平衡。$\beta$ 越大，越保守。

### 和 Atari 的对照

把两边的要素摆在一起看，会清楚很多。

状态。Atari 是像素帧，固定大小，信息完整。语言是文本，长度可变，且包含模型自己生成的内容。

动作。Atari 是十几个按键。语言是十几万个 token，而且很多 token 在语义上等价。

奖励。Atari 每步都有分。语言通常只有一个终局分数，而且这个分数本身是另一个模型给的，有噪声。

回合长度。Atari 几百到几千帧。语言几十到几千个 token，长度本身还会被策略影响。

最后一条值得单独说。模型可以选择什么时候停止生成，这本身就是一个动作。如果奖励与长度正相关，模型会学会写得更长，哪怕内容没有变好。这个现象在 RLHF 里非常常见，第十章会详细讲。

### 一个容易忽略的细节

语言模型的策略是**自回归**的，每个 token 的条件依赖于之前所有 token。这意味着策略的分布在整段序列上是一个巨大的联合分布，而我们实际优化的是逐 token 的条件分布。

在计算概率时，整段回答的对数概率是各个 token 对数概率之和。

$$
\log\pi_\theta(y\mid x) = \sum_{t=1}^{T}\log\pi_\theta(y_t\mid x,y_{<t})
$$

这个分解在后面计算重要性采样比、KL 散度时都会用到。它也是“逐 token 处理”这种实现方式的依据。

### 这一部要解决的问题

把生成看成决策之后，接下来的问题很自然：奖励从哪来？

如果每一步都有明确的对错，比如数学题的答案，事情就简单。但大多数任务没有标准答案，只有“这个回答比那个好”这样的相对判断。下一章讲怎么把这种比较变成一个可以优化的分数。
