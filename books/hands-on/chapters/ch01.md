## 装好一个能跑实验的环境

本书的代码都能在本机跑。一台普通的笔记本，有独立显卡更好，没有也能完成前九章的实验。

装环境这件事在过去几年变得简单了很多，但仍然是最容易卡住新手的环节。这一章把需要的东西列清楚，也给几个排错的思路。卡住的时候不用慌，多数问题来自版本不匹配，而不是你写错了什么。

### 需要的东西

四个 Python 包，加一个可选的显卡驱动。

**gymnasium** 提供标准的环境接口，CartPole、LunarLander 这些经典任务都在里面。它是 OpenAI gym 的维护版本，接口有细微改动，网上的老代码可能需要改一行。

**torch** 用来写神经网络。装的时候注意选对版本，CPU 版和 CUDA 版是分开的包。装错了不至于报错，只是用不上显卡。

**numpy** 和 **matplotlib** 一个算数一个画图，几乎所有实验都会用到。

如果机器上有 NVIDIA 显卡，先确认驱动能用。命令 `nvidia-smi` 会打印显卡型号和驱动版本，看不到输出说明驱动没装好，这时候装 CUDA 版的 torch 也用不上。

### 三种装法

最简单的是 conda，适合不想折腾的人。

```bash
conda create -n rlbook python=3.11 -y
conda activate rlbook
pip install gymnasium torch matplotlib
```

用 venv 也可以，和系统 Python 隔离就行。

```bash
python -m venv .venv
.venv\Scripts\activate
pip install gymnasium torch matplotlib
```

有显卡的话，torch 建议按官网给出的命令装，它会自动匹配 CUDA 版本。直接 `pip install torch` 装到的通常是 CPU 版，跑小网络没什么差别，但心理上会不踏实。

### 验证一下

装完跑这段，能打印出版本和显卡状态就说明通了。

```python
import gymnasium as gym
import torch

print("gymnasium", gym.__version__)
print("torch", torch.__version__)
print("cuda", torch.cuda.is_available())

env = gym.make("CartPole-v1")
obs, info = env.reset(seed=0)
print("observation", obs.shape, obs.dtype)
print("actions", env.action_space.n)
env.close()
```

正常情况下会看到观测是长度为四的向量，动作是两个。如果 `env.reset` 报错说没有 `render_mode`，检查 gymnasium 的版本，零点二六之后的接口都是现在这个样子。

### 显卡值不值得用

本书的实验规模很小，一个四维输入、两层一百二十八的全连接网络。这种网络在显卡上跑，瓶颈不在计算，而在每一步把数据搬到显卡的开销。所以你会看到一个反直觉的现象，同一个实验在 CPU 上可能比显卡更快。

什么时候显卡才有用？网络变大、批量变大、环境变多的时候。连续动作的实验、语言模型的训练，才真正需要显卡。

代码里我留了一个开关，用环境变量控制设备。

```python
import os
import torch

def pick_device():
    if os.environ.get("RLKIT_DEVICE", "").lower() == "cpu":
        return torch.device("cpu")
    if torch.cuda.is_available():
        return torch.device("cuda")
    return torch.device("cpu")
```

跑实验时这样用。

```bash
set RLKIT_DEVICE=cpu
python run_dqn_cartpole.py
```

### 卡住时怎么问 AI

用 AI 帮忙排错已经是很日常的事，但提问方式决定了效率。三个经验。

第一，把完整的报错贴进去，包括最后几行的文件路径和行号。只说“跑不起来”，对方只能猜。

第二，说清楚版本。`gymnasium 0.29` 和 `1.0` 的接口有差别，`torch 2.0` 和 `2.4` 也有。把验证脚本的输出一起贴上，能省掉很多来回。

第三，要求最小复现。如果对方给了一大段代码，先让对方缩到一个能跑的最小例子，确认那个例子在你的机器上通过，再往你的代码里搬。

还有一个容易被忽略的点。AI 给出的代码经常是“看起来对”的，尤其是强化学习这种带随机性的代码，跑起来不报错但学不会，很难一眼看出问题。所以每次改动之后，先用小的回合数跑一遍，看曲线有没有动静，再决定要不要加长训练。

### 本书的目录

代码放在书的仓库里，按实验分文件。

```text
books/code/hands-on/
├── rlkit.py              公用工具：随机种子、设备、评估、结果保存
├── gridworld.py          自己写的网格世界
├── run_gridworld.py      表格 Q 学习
├── run_dqn_cartpole.py   DQN 与两组消融
├── run_reinforce.py      策略梯度
├── run_ppo.py            PPO
├── plots.py              画图用的小函数
└── results/              每次实验的曲线，JSON 格式
```

每个脚本都能单独跑，跑完把结果写进 `results/`，插图脚本再从那里读数据。这样图和代码是分开的，改图不用重跑实验，改实验也不用动图。
