## 换个环境：从 CartPole 到 LunarLander

CartPole 太简单了。四个观测值，两个动作，几百局就能学会。真实问题不会这么友好。

这一章换一个稍难的环境，看同一个算法会遇到什么新问题。重点不是把 LunarLander（月球着陆器，Box2D 环境）训到多好，而是建立一套换环境时的检查流程。

### LunarLander 是什么

一个着陆器从上方降落，要用主引擎和两个侧向推进器把它稳稳地放在两块着陆垫之间。观测有八个值，包括位置、速度、角度、角速度，以及两条腿是否着地。动作有四个，不点火、主引擎、左推进器、右推进器。

奖励的设计比 CartPole 复杂得多。靠近着陆垫、速度低、角度正，每一步都有正奖励；坠毁扣一百分；成功着陆加一百分；用侧向推进器每次扣一点小分。一局通常在几百到一千步之间。

这些数字说明了一件事，奖励的大小和频率会直接影响学习的难度。CartPole 每步一分，信号均匀；LunarLander 的奖励有大有小，还有稀疏的终局奖励。

### 八个观测值的含义

前两个是着陆器的横纵坐标，原点在两块着陆垫中间的上方。中间四个是速度和角度，后两个是左右两条腿是否接触地面，只有零和一两种取值。

我们拿随机策略跑了一百局，把路上见到的所有观测统计了一遍。横坐标在负一点零到一点零之间，纵坐标在负零点三四到一点六九之间，横向速度到正负二，纵向速度到正负二，角度到正负三点五弧度，角速度到正负六。后两维只有零和一，标准差都是零点一二，说明随机策略大约有十二个百分点的步数有一条腿着地。

这些范围很不整齐。位置量级在一，角速度量级在六，腿接触在零和一。如果直接送进网络，量级大的维度会在第一层占掉大部分梯度，量级小的维度几乎不起作用。常见的处理有两种，按维做标准化，或者把每个维度除以它的大致范围。

CartPole 不需要这一步，因为它的四维都在正负五以内，量级接近。换环境时这是一个容易漏的检查点，网络不报错，只是学得慢，很难归因。

### 奖励的解剖

随机策略每一步的平均奖励是负二点一三，绝对值平均是三点三五。两个数差这么多，说明奖励分布很偏，大部分步是小负数，少数几步是大的正数或负数。

分布的形状大致是这样。侧向推进器每按一次扣零点零三，纵向速度每步有一个小惩罚，这两项合起来构成日常开销。着陆成功一次加一百，坠毁一次扣一百，这两个是稀疏事件，一局最多发生一次。

环境文档里还有一个细节容易被忽略，两条腿同时着地时每步有额外奖励，这条奖励鼓励智能体稳稳停住而不是飞过去。它让“成功”变成了一个过程而不是一个瞬间。

这种奖励结构对学习的影响很直接。一局里绝大多数步骤的信号是“慢慢变差”，真正决定成败的是最后那一下。智能体需要把最后那一下的功劳分给前面几十步的动作，这个信用分配的距离比 CartPole 长得多。

### 逐行看清单

观测维度从四变八，网络输入层要改。这一步不会错，改错了会直接报形状错误。

观测范围要小心。位置在正负二点五以内，角速度能到正负十，后两维是零一。不做处理也能跑，但学习会慢，因为网络要把大部分容量花在拟合尺度差异上。最简单的处理是 RunningMeanStd，用训练中见到的数据在线估计均值和方差，评估时用同一套统计量。

动作从两个变四个，输出层宽度跟着变。这里有一个隐蔽的坑，如果代码里把动作数写死了，环境换了不会报错，只会拿前两个动作去用，策略永远学不会用主引擎。

奖励尺度和回合长度这两项改动最大，也最容易只改一半。它们的具体调法放在后面两节，这里先记住它们不是顺手改一行的事。

成功标准也不同。CartPole 到五百步就是满分，LunarLander 没有上限，官方给的线是一百局平均两百分。评估时要按这个标准算，不能只看单局最高分。

奖励尺度变了，学习率要跟着调。CartPole 用千分之一，LunarLander 上这个值可能太大，因为奖励的绝对值大了几十倍，梯度也大。常见的做法是把奖励缩放，或者把学习率降到万分之一。

回合变长，折扣因子要更接近一。如果 gamma 还是零点九九，一千步之后的奖励几乎被完全忽略，智能体看不到“最终着陆成功”这个信号。这时通常取零点九九五或者更高。

网络要变大一些。八个输入值，四个动作，中间层一百二十八可能勉强够，但更稳的做法是加到两百五十六。

### 一个实际的坑

换环境时最常见的错误是直接复制超参数。

把 CartPole 的配置搬到 LunarLander，结果通常是前期分数一直是负的，看起来完全没学。这时候容易怀疑算法有问题，其实只是学习率太大，网络在早期就被推到一个很差的位置，之后再也爬不出来。

解决办法是先做一个小的诊断。用学习率除以十跑一百局，看曲线有没有变化。如果有变化但很慢，说明方向对了，可以把学习率调到中间值。如果完全没变化，再查别的地方。

### 学习率诊断的两种做法

除以十跑一百局是最省事的做法，但它只能告诉你方向，不能告诉你最优点在哪。更靠谱的做法是三点扫描，取原值的十分之一、原值、原值的十倍，各跑一个短预算，看三根曲线的早期斜率。

斜率可以从第一轮评估点算，不必等跑完。早期斜率比最终成绩更能反映学习率是否合适，因为最终成绩被随机性扰乱得更多。

还有一种更快的诊断，看价值损失。学习率太大时，价值损失会在前几轮剧烈震荡，一会儿几百一会儿几千；学习率太小时，价值损失下降得很慢，几乎是一条平线。把价值损失单独画出来，几百步就能判断，不用等一局跑完。

这三种诊断针对的是同一件事，但成本不同。价值损失最便宜，三点扫描最贵，除以十居中。实际调试时先用价值损失排除明显错误，再用三点扫描定值。

### 奖励缩放

奖励缩放是换环境时最容易被低估的一步。

```python
scale = 0.1
reward_scaled = reward * scale
```

把奖励乘零点一，效果等于把学习率乘十，也等于把价值网络的目标缩小十倍。它不改变最优策略，因为乘一个正常数不改变行动之间的排序，但它改变了梯度的尺度。

缩放多少合适，看一局的回报量级。目标是让一局的折扣回报落在几十到几百之间，和 CartPole 差不多。LunarLander 一局能到正负几百，乘零点一之后在正负几十，刚好。Atari 的分数动辄上万，常见做法是截断到正负一。

缩放的副作用是它和折扣因子有交互。缩放不改变回报的相对结构，但会让价值网络的目标变小，评论家学得更慢。所以缩放之后要把价值损失系数重新看一眼，必要时调大。

### 训练要多久

LunarLander 比 CartPole 难一个量级。用 PPO 的话，通常要几十万到上百万步才能稳定着陆。用 DQN 也能做，但需要更仔细地调参，而且更容易崩。

这个量级意味着两件事。第一，训练时间从几分钟变成几十分钟到几小时。第二，随机性的影响更大，同一个配置跑两次，结果可能差很多。

所以在这个规模上，单次实验没有意义，必须跑多个种子看分布。第十一章会专门讲这件事。

表里最扎眼的是最上面一行。两万步时评估是负六百，比随机策略的负一百九十二还差得多。这不是评估写错了，是策略真的在主动坠毁。训练初期的网络输出几乎是随机的，但它对某些动作有微弱的偏好，这些偏好刚好让着陆器往下扎。随机策略至少还会漂一会儿，一个坏策略比随机更糟，这是强化学习里常见但反直觉的现象。

六万步之后回到随机水平附近，十万步开始有正值，之后在一百上下震荡。两个种子的曲线不同步，种子零在一百上下，中间掉到过负四十；种子一在负五十和一百二之间来回。这种震荡不是评估噪声，五局的评估确实抖，但训练回报的滑动平均也在同一量级上抖。

二十万步的结果离两百分的线还很远。按这个速度，要稳定过线大概需要两三倍的预算，也就是五十到六十万步。这和前面说的几十万到上百万对得上。重要的是，这个数字是跑出来的，不是拍脑袋估的。做新任务时，先用小预算跑一条曲线，看斜率和震荡幅度，再决定总预算，比直接拉到一百万步稳妥。

还有一个细节，种子零和种子一在同一个预算下的评估差了一倍。这说明在二十万步这个尺度上，单次实验的结论不可靠，至少三个种子才能看出趋势。

### 如果需要连续动作

LunarLander 有离散版本也有连续版本。如果任务要求输出连续的推力大小，DQN 就没法用了，因为它需要对每个动作算 Q 值再比较，连续动作没法枚举。

这时候要换算法。常见的选择是 DDPG（deep deterministic policy gradient，深度确定性策略梯度，2016 年提出）、SAC（soft actor-critic，最大熵演员评论家，2018 年提出），它们直接输出连续动作。这两个算法这里不展开，先把离散动作的流程走完。

### 动作分布能看出策略长什么样

四个动作的分布比 CartPole 有信息量，因为四个动作的物理含义不同。

二十万步的实验里，种子零后期四个动作的占比是零点二九、零点一四、零点四三、零点一四，种子一是零点一八、零点三六、零点二一、零点二五。不点火的占比在两成到三成之间，主引擎只有一成四到三成六，两个侧向推进器分掉了剩下的部分。

种子零明显依赖右推进器，种子一依赖主引擎略多。两个种子都学会了“不要一直点火”，这是合理的，因为点火会消耗燃料并带来副作用。具体用哪个推进器去抵消偏移，它们给出了不同的答案，最后都能到一百上下的回报。

这种分化的现象在 CartPole 上看不到，因为两个动作完全对称。到了动作有不同物理含义的环境，动作分布就成了一个诊断工具，它能告诉你策略是不是在用某个不该用的动作，比如一直靠侧向推进器漂移而不下降。

记录动作分布很简单，每局开始时清零，每步累加，结束时写进结果文件。它不增加任何计算量，但能在回报正常时发现异常。

### 随机性从哪里来

LunarLander 的随机性主要有两个来源，初始状态和物理步进。

初始状态是随机的，着陆器初始位置在高空一个小区域里，带一个随机的初速度和角度。同一份策略碰上不同的开局，结果差别很大，有的开局几乎垂直下落，有的开局一开始就歪了。这就是为什么评估要多跑几局，单局的结果说明不了什么。

物理步进默认是确定性的，同样的状态和动作得到同样的下一状态。但 Box2D 的接触求解对初始条件很敏感，一点点差异会放大成完全不同的轨迹。这种敏感不是噪声，它意味着回报的方差天然很大，即使策略完全固定。

环境还有一个风力选项，默认关着。打开之后会叠加随机的横向风，难度明显上升，适合做鲁棒性实验。入门阶段不要开，先把基本流程跑通。

这些随机源里，只有初始状态能用 `reset(seed=...)` 完全控制。物理的那部分虽然确定，但对浮点误差敏感，换一个平台、换一个 BLAS 库就可能跑出不同的轨迹。要求严格复现时，这一点要写进实验记录里。

### 观测归一化的实现

归一化不需要预先知道范围，用在线统计就行。

```python
class RunningMeanStd:
    def __init__(self, shape, eps=1e-4):
        self.mean = np.zeros(shape, dtype=np.float64)
        self.var = np.ones(shape, dtype=np.float64)
        self.count = eps

    def update(self, x):
        x = np.asarray(x, dtype=np.float64)
        b_mean, b_var, b_count = x.mean(0), x.var(0), x.shape[0]
        delta = b_mean - self.mean
        total = self.count + b_count
        self.mean += delta * b_count / total
        m_a = self.var * self.count
        m_b = b_var * b_count
        self.var = (m_a + m_b + delta ** 2 * self.count * b_count / total) / total
        self.count = total

    def __call__(self, x):
        return np.clip((x - self.mean) / np.sqrt(self.var + 1e-8), -10, 10)
```

这段代码合并两个正态总体的方差，写法比看起来复杂，但不难用。训练时每采一步就更新一次，评估时只做变换不再更新。裁切到正负十能防止极端值破坏网络，LunarLander 偶尔会出现很大的角速度，不裁的话一次更新就能把第一层带飞。

后两维只有零和一，归一化之后它们是正负几的连续值，物理含义变模糊了。如果想把它们当开关用，可以跳过后两维，只归一化前六维。这个细节不影响结果，但写论文时要说清楚。

### 检查清单怎么用

每次换环境，按顺序过一遍。

先跑随机策略，记录平均回报和回合长度。这个数字是底线，任何算法都应该显著超过它。

再看观测的范围和分布。如果某一维的取值范围特别大，考虑归一化。如果分布明显不对称，考虑换一个表示。

然后调学习率和折扣因子。这两个参数的影响最大，优先调它们。

最后调网络结构和训练预算。网络太小欠拟合，太大过拟合且慢。训练预算不够，曲线还没抬起来就停了。

这套流程不保证一次成功，但能让你在失败时知道该往哪里看。下一章把“怎么让实验可重复”这件事讲清楚，它是上面所有工作的前提。

### 截断和终止在这一章里分得很开

LunarLander 有一个一千步的时间限制，到点就 `truncated`，不是坠毁也不是着陆。这个区别在长回合任务上比 CartPole 重要得多。

如果代码里把截断当成终止，智能体会认为“到了一千步世界就消失”，于是学会在接近一千步时放弃，因为再努力也没有后续奖励了。表现出来是很多局停在一千步附近，回报不低但也不高，看起来像学会了悬停，其实是学会了拖时间。

正确处理是在算 GAE 时对截断继续自举。代码里用 `done = term` 而不是 `term or trunc` 做非终止标志，回合的切分用 `term or trunc`。这两个变量名字很像，一个管数学，一个管循环，写反了不会报错，只会让智能体变懒。

```python
nxt, reward, term, trunc, _ = env.step(action)
episode_over = term or trunc          # for resetting the env
nonterminal = 1.0 - float(term)      # for bootstrapping
```

在 CartPole 上这个区别不明显，因为五百步的上限很少被碰到，而且碰到的时候策略已经满分了。换到 LunarLander，一百步的悬停和一千步的悬停差很多，错误会直接污染训练信号。

### 怎么判断它真的着陆了

回报高不等于着陆成功。一个策略可以在空中飘一千步，每步拿一点小奖励，累积起来也是正数，但它没有完成任何任务。

评估要分开看三件事。着陆成功的比例，也就是两条腿都碰到垫子并且速度足够低；坠毁的比例，回报低于负一百的局；平均回合长度。三个数一起看，才知道策略在干什么。

我们这组二十万步的实验里，坠毁比例是百分之三十三和百分之三十八，平均回合长度是两百四十七和三百三十三步。回报一百上下，主要来自悬停和慢速下降的累积，真正着陆的局不多。如果只看回报，会高估它的水平。

评估局数也要注意。五局的评估只能看量级，不能看细节，一局的成败就能把均值拉动一百。要用它做决策，至少三十局，并且把三个数一起报，不要只报一个平均回报。三个数放在一起，读者才看得出这一百分是飘出来的还是落下来的。

### 换环境这件事本身要花多久

最后说一个经验数字。从 CartPole 换到一个新环境，把流程跑通到能用，通常要半天到两天。时间不在写代码上，在调参和等结果上。

缩短这段时间的办法是把检查点做成脚本。随机基线、观测统计、奖励统计、短预算学习曲线，这四个东西各写一个小脚本，换环境时依次跑一遍，一小时内就能知道这个环境的基本脾气。剩下的时间才是调参。

这套东西看起来像额外工作，其实是在给后面的每一次实验省时间。第十一章会把它们打包成可复用的流程。

最后补一句关于记录的话。换环境时最贵的成本不是算力，是记不住自己试过什么。每换一组超参数就在笔记里写三行，改了什么、为什么改、结果如何，十分钟能写完，事后能省下几个小时。我见过最多的浪费，是隔了两周又想不起来某个配置到底跑没跑过，只好再跑一遍。
