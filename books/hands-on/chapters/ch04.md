## 自己做一个网格世界

用现成的环境有个问题，你不知道细节。CartPole 的物理参数、奖励规则、终止条件，都是别人定好的，遇到不对劲的地方只能猜。

自己写一个环境就不同了。地图、奖励、规则全在自己手里，改一个数就能看到结果怎么变。这一章写一个最简单的网格世界，它只有四十个格子，却足以演示后面所有算法的核心机制。

### 地图用字符画

把地图写成几行字符串，一眼就能看出形状。

```python
MAP = [
    "S..#....",
    ".#.#.##.",
    ".#...#..",
    ".#.#.#.#",
    "...#...G",
]
```

`S` 是起点，`G` 是终点，`#` 是墙，`.` 是空地。五乘八，四十个格子。图 4-1 是它的样子。

![网格世界的地图：灰色是墙，起点在左上，终点在右下，中间留了两条绕行的路](../images/04/fig04-1.png)

为什么要留岔路？因为一条直线的迷宫太简单，随机走也能很快碰到终点，看不出算法有没有学到东西。有了岔路和死胡同，智能体必须记住“这条路走不通”，价值函数才有发挥的余地。

### 地图的几个数

这张地图看起来随手画的，其实有几个可以量出来的性质，它们决定了任务有多难。

用宽度优先搜索数一遍，四十个格子里有十二个是墙，二十八个是空地。二十八个空地全部从起点可达，没有孤岛。从起点到终点的最短路是十一步，最远的格子要走十三步。

```python
from collections import deque

h, w = len(MAP), len(MAP[0])
start = next((r, c) for r in range(h) for c in range(w) if MAP[r][c] == "S")
dist = {start: 0}
queue = deque([start])
while queue:
    r, c = queue.popleft()
    for dr, dc in ACTIONS:
        nr, nc = r + dr, c + dc
        if 0 <= nr < h and 0 <= nc < w and MAP[nr][nc] != "#" \
                and (nr, nc) not in dist:
            dist[(nr, nc)] = dist[(r, c)] + 1
            queue.append((nr, nc))
print("reachable", len(dist), "shortest", dist[goal])
```

这几个数各有各的意义。

最短路是十一步，这个数字就是成绩的上限。后面所有算法学出来的平均步数，不可能低于它。评估时看到平均 11.0，就知道策略已经最优，不用再调参数。

最远距离是十三步，比最短路只多两步。这说明这张地图的绕路余地很小，绕错一格就要多走两三步。任务不难，但有明确的惩罚。

可达格子等于空地总数，说明地图是连通的。这一点在做实验时很重要，如果有一个不可达的区域，那个区域的状态永远不会被访问，Q 表里那一块永远是零，画图时会出现一块奇怪的颜色，让人以为算法有问题。

死胡同只有一个，就是终点本身。这条数值得想一想，意思是这张地图没有真正的死角，所有分支最终都能回到主路，只是多绕几步。所以“记住哪条路走不通”这件事在这里其实用不上，价值函数的差别只体现在长短上。盖房子时会发现，想要真正的死胡同，得故意画一个三面是墙的格子。

真正的难度来自撞墙。随机走一局，平均要走一百八十一步，其中八十七步是撞在墙上。差不多一半的动作是无效的。这个比例说明探索在这张地图上效率很低，随便乱撞很难碰到终点。

### 状态与动作

状态用一个整数表示，等于行号乘宽度加列号。这样四十个格子对应零到三十九。

```python
def _state(self):
    r, c = self.pos
    return r * self.w + c
```

用整数而不是坐标对，是为了方便查表。第五节的 Q 表就是一个四十乘四的数组，行是状态，列是动作。

反过来的换算也要有，调试时经常要把编号还原成位置。

```python
def to_rc(state, width):
    return divmod(state, width)

print(to_rc(37, 8))     # (4, 5)
```

三种表示方式各有适用场合。

整数编号最省，查表用一次索引，画图时用一次 divmod 就能还原。缺点是编号本身没有语义，三十七这个数字不告诉你它在哪，看 Q 表时要不停换算。

坐标对可读性好，写规则时用它更自然，判断越界、判断撞墙都直接。缺点是查表要先算编号，多一步。

独热编码把状态铺成一个长度为四十的向量，里面只有一个一是。它适合喂给神经网络，因为网络需要连续输入。缺点是浪费，四十维里三十九维是零，地图一大就没法用了。本书后面的深度方法用的是原始观测，不做独热。

选哪种取决于要不要查表。表格方法用整数，函数逼近用连续表示，中间的地图逻辑用坐标对。三者之间互相转换的代码只有几行，不值得为了统一而牺牲方便。

动作有四个，上下左右。

```python
ACTIONS = [(-1, 0), (1, 0), (0, -1), (0, 1)]   # 上 下 左 右
```

撞墙的处理是原地不动，不额外惩罚。这样的设计让智能体在墙边不会受到特别的惩罚，学起来更容易，但也让它在墙边更难判断方向。另一种做法是撞墙给负奖励，会更严格，代价是训练变慢。

### 一步的完整逻辑

```python
def step(self, action):
    dr, dc = ACTIONS[action]
    r, c = self.pos
    nr, nc = r + dr, c + dc
    if self._cell(nr, nc) == "#":
        nr, nc = r, c          # 撞墙就留在原地
    self.pos = (nr, nc)
    self.steps += 1

    cell = self._cell(nr, nc)
    reward, terminated = -0.01, False
    if cell == "G":
        reward, terminated = 1.0, True
    elif cell == "X":
        reward, terminated = -1.0, True
    truncated = self.steps >= self.max_steps
    return StepResult(self._state(), reward, terminated, truncated, {})
```

每一步扣零点零一，走到终点加一，掉进陷阱减一。这个小的步数惩罚很重要，它让智能体倾向于走更短的路，而不是在原地转圈。

返回值用了一个小数据类，同时实现了 `__iter__`，所以既能按属性取，也能像 gymnasium 那样解包五个值。

```python
@dataclass
class StepResult:
    state: int
    reward: float
    terminated: bool
    truncated: bool
    info: dict

    def __iter__(self):
        return iter((self.state, self.reward, self.terminated,
                     self.truncated, self.info))
```

### 撞墙的三种写法

撞墙怎么处理是一个真正的设计决定，不是随手写写。四种常见写法的实测结果如下，每种都训练四百回合，学习率零点一，折扣零点九五，探索率从零点三线性退到零点零二。

::: {.tabcap}
表 4-1　撞墙处理方式的对比
:::

| 处理方式 | 每局撞墙次数 | 达到九成成功所需回合 | 成功时平均步数 |
| --- | --- | --- | --- |
| 原地不动，不罚 | 4.16 | 第一个窗口 | 11 |
| 原地不动，罚 0.1 | 1.71 | 第一个窗口 | 11 |
| 原地不动，罚 1.0 | 1.64 | 第一个窗口 | 11 |
| 撞墙即终止，罚 1 | 0.73 | 329 | 11 |

第一列的数字是训练期间每局平均撞墙次数，它反映的是探索行为。不罚的那一版撞得最多，因为撞了也没有代价。罚了之后撞墙次数掉到四成左右，说明智能体学会了避开墙。

第二列是学习速度。前三种在第一窗口就达到九成，也就是说二十局之内就学会了。最后一种要三百二十九局，慢了十倍以上。原因很直接，撞墙即终止等于把一次错误放大成整局的失败，探索期大量的撞墙转化成大量的负样本，价值函数被这些负值占满，学到通路需要更长时间。

第三列全都一样。四种写法最终都学到了最优的十一步，说明在地图不变的前提下，撞墙的处理只影响学习效率，不影响最终结果。

回到前面那句话，加惩罚会让训练变慢。在这张四十格的小地图上，惩罚版的墙上表现反而更干净，没有变慢。地图变大之后情况不同，状态多、探索期长，负奖励会在早期占主导，那时候才会看到明显的拖慢。所以这个说法不是错的，只是它的代价在大地图上才显现。

实践中的建议是按任务选。想要简单、想看价值函数平滑，用原地不动不罚。想让策略更谨慎、想在部署时避免反复撞墙，加一个小惩罚。想让任务变成“一步走错就完蛋”的硬约束，用终止，但要准备好更长的训练时间。

### 加一点不确定性

现实世界的动作不会百分百按你想的执行。地上有水会滑，轮子会打滑，机械臂有间隙。在环境里加一点随机，能让学出来的策略更结实。

```python
def step(self, action):
    dr, dc = ACTIONS[action]
    if self.slip > 0 and np.random.rand() < self.slip:
        dr, dc = ACTIONS[np.random.randint(len(ACTIONS))]
    ...
```

`slip` 设成零点一，意味着有一成的概率走偏。这时候最优策略会变得保守，它会避开紧贴陷阱的路线，因为一次打滑就可能掉进去。这个变化在第五节的策略图里能看出来。

### 滑倒概率该设多少

滑倒的概率不是越大越好，它有一个合适区间。

在这张地图上设零点一，训练之后用贪心策略评估一百局，成功率还是一百，但平均步数从十一步涨到十二点二步。多出来的一点二步是因为打滑把人推离了最优路线，要重新找回来。

打滑概率为零时，随机走一局撞墙八十七次，平均一百八十一步。加到零点一时，撞墙九十次，步数一百八十七。差别很小，因为随机走的动作本来就乱，再加一点乱也看不出区别。这个对比说明一件事，评估噪声的影响要看基线，在一个本来就随机的策略上看不出噪声的作用。

真正该关心的是最优策略在噪声下的表现。十一步变十二点二步，成功率不掉，说明这条主路径足够宽，打滑一次不会致命。如果地图里有一条紧贴陷阱的窄路，打滑就会让它变成高风险路线，学出来的策略会绕远。

选 `slip` 的经验是这样的。零点零五到零点二对应“轻微的不确定性”，策略会稍微保守，但成绩下降不多。零点三以上对应“强噪声”，这时候最优策略会明显改变形状，学习也变慢。超过零点五基本等于每次都在乱走，任务失去意义。

有一个坑要提一下。打滑应该作用在动作上，不应该作用在结果上。有些实现写成“执行动作之后，有一成概率把位置随机挪一格”，那会让智能体穿墙。正确的写法是先决定实际执行的方向，再走一步，撞墙的判断放在后面，这样打滑只会把人带到墙上，不会带穿墙。

### 为什么不用现成的环境库

自己写环境还有一个好处，它逼你想清楚几件事。

奖励怎么设计。每步扣多少，终点给多少，中间要不要给额外奖励。这些决定直接影响学出来的行为，而且没有标准答案。

状态怎么表示。用整数编号，还是用坐标，还是用局部视野。状态里包含什么，不包含什么，决定了智能体能看到多少信息。

回合怎么结束。走到终点结束，掉陷阱结束，还是走满两百步强制结束。截断和终止的区别在这里第一次变得具体。

想清楚这三件事，再看别人写的环境，会很快看出它的设计取舍。

### 地图怎么改会更难

这张地图难度刚好，改了就会变。下面四种改法都跑过，每一步都算了最短路、随机策略成功率，再训四百回合看能不能学会。

```text
改法      格子数  最短路  随机成功率  达到九成  成功时步数
原图        40      11      25.5%     第一个窗口    11
加宽        80      23       0.5%        37        23
堵住路口    40      15      13.5%         3        15
加陷阱      40      11       4.5%        44        17
堵死通路    40     不可达      0%       学不会
```

加宽是把宽度从八加到十六。状态数翻倍，最短路从十一变成二十三，随机策略的成功率从四分之一掉到百分之零点五，要靠三十七回合才能学会。这是最温和的加难方式，任务还是那个任务，只是变长了。

堵住一个路口是堵掉起点右边那一格，逼着智能体走左侧的长路。最短路从十一变成十五，随机成功率从百分之二十五掉到百分之十三，其他不变。这个改动最有效率，它只改变路径长度，不改变任务性质。

加陷阱是在主路旁边放一个减一的格子。最短路还是十一，但最优策略会绕开陷阱，成功时平均步数从十一涨到十七。注意这里出现了一个典型的冲突，最短的路和安全的路线不是同一条，算法选了安全的，因为掉进陷阱的代价太大。打滑概率一加上去，这个选择会更明显。

最后一行是事故。我第一次把走廊中间的格子堵掉，想着只是让路长一点，结果整个终点区域跟起点断开了。可达格子从二十八个变成十三个，最短路算不出来，训练四百回合全部失败。这个错很容易犯，因为地图是字符画，看上去只是少了一个点，实际把唯一的通道切断了。所以改完地图先跑一遍连通性检查，再开始训练。

四个有效改法里，加宽和堵路口都能把任务变长，区别在探索难度。加宽之后随机探索的成功率掉了五十倍，因为地图太大，乱走碰不到终点；堵路口只掉了一半，因为地图尺寸没变，随机走的覆盖效率差不多。如果目的是让算法学得更久而不是让探索更难，选堵路口。

### 奖励设计的三条规矩

奖励是最容易设计错的部分，因为它看起来只是几个数字。

第一条，每一步都要有代价。这张地图上每步扣零点零一，看起来微不足道，它做的事情是打破平局。如果每步奖励是零，那么绕远路和走近路的总回报完全一样，最优策略不唯一，学出来的策略可能一直在绕圈。加上一个很小的负值，绕圈就变成了坏事，短路径自然胜出。

零点零一这个数也不是随便挑的。十一歩的代价是零点一，终点的奖励是一，比是十比一，信号够强。如果每步扣零点一，十一步的代价超过奖励，智能体就学不会走过去了，因为它宁可原地不动。这个比例要保证“到达”比“不走”划算。

第二条，奖励的尺度要接近。终点加一，陷阱减一，步数扣零点零一，三个数在同一量级，梯度不会失衡。如果终点给一千，步数扣零点零一，那么早期的随机探索拿到的总回报几乎全是终点那一千，价值函数的取值范围被拉得很大，学习率就得跟着调。尺度统一之后，一套超参数能用在多个任务上。

第三条，想让智能体学到什么就奖励什么。这张地图只奖励到达，所以它学到的就是最短路，中间不会绕去看风景。如果在某个角落放一个额外奖励，它会绕过去，因为总回报更高。这个机制很有用，也很危险，你奖励什么就会得到什么，包括你没想到的副作用。经典的失败例子是赛艇游戏，奖励设计成拿到分数，结果智能体学会了在原地转圈刷分，不去完成比赛。

### 和 gymnasium 对齐

如果希望自己的环境能被现成的工具识别，可以实现 `gymnasium.Env` 接口并注册。

```python
import gymnasium as gym

class GridWorldEnv(gym.Env):
    observation_space = gym.spaces.Discrete(40)
    action_space = gym.spaces.Discrete(4)
    ...
```

这不是必须的。本书后面的代码直接用自己的接口，因为简单。但如果你要做成库给别人用，对齐标准接口会省掉很多解释成本。

### 补全注册要的几行

上面那个类只是骨架，真正能跑要补三样东西。空间对象要在 `__init__` 里建，`reset` 要接受 `seed` 并调用父类，`step` 要返回五元组。

```python
import gymnasium as gym
import numpy as np
from gymnasium import spaces

class GridWorldEnv(gym.Env):
    metadata = {"render_modes": []}

    def __init__(self, slip=0.0, max_steps=200):
        super().__init__()
        self.inner = GridWorld(slip=slip, max_steps=max_steps)
        self.observation_space = spaces.Discrete(self.inner.obs_dim)
        self.action_space = spaces.Discrete(self.inner.n_actions)

    def reset(self, *, seed=None, options=None):
        super().reset(seed=seed)      # this also seeds self.np_random
        self.inner.reset()
        return self.inner._state(), {}

    def step(self, action):
        out = self.inner.step(int(action))
        return out.state, out.reward, out.terminated, out.truncated, out.info
```

注册和创建各一行。

```python
gym.register(id="GridWorldBook-v0", entry_point="my_env:GridWorldEnv")
env = gym.make("GridWorldBook-v0", slip=0.0)
```

注册的第二行参数是模块名加类名，冒号前面是模块，后面是类。模块必须在 Python 能找到的路径上，否则 `gym.make` 时会报导入失败。这个报错信息不长，但指向的是一个你已经写好的文件，容易让人迷惑。

写完跑一遍官方的检查器，能挡掉大部分问题。

```python
from gymnasium.utils.env_checker import check_env

check_env(env.unwrapped, skip_render_check=True)
```

这个检查器会做几件事。跑一次 `reset` 看返回的对不对。跑几步 `step` 看返回的观测在不在 `observation_space` 里。检查 `reset(seed=...)` 两次是不是得到同样的起点。检查动作空间采样出来的值能不能用。

我们这个环境全部通过。`reset` 两次同一个种子都得到零，观测零在空间里，动作采样出来是 `numpy.int64`，环境能接受。

检查器没有报错不代表写对了，这一点要说清楚。它检查的是接口形状，不是语义。一个把奖励全写成零的环境也能通过检查，一个把 `terminated` 和 `truncated` 写反的环境也能通过。接口正确和任务正确是两件事，前者能自动检查，后者只能自己算一遍。

如果想让 `gym.make` 支持步数上限，把 `max_episode_steps` 传进去，它会自动套一层 `TimeLimit`。

```python
env = gym.make("GridWorldBook-v0", max_episode_steps=50)
```

这一步经常被忘记。忘了的话，环境内部的 `truncated` 还是按自己的 `max_steps` 判断，外面的 `TimeLimit` 又有一套判断，两个上限同时生效，短的先触发。调试时看到回合长度不对，先查这里。

### 常见坑

自己写环境有五个坑，几乎每个人都会踩到至少两个。

第一个是用全局随机。`np.random.seed(seed)` 改的是全局状态，会影响同一个进程里所有用到随机的地方，包括你的探索策略和网络的初始化。正确的做法是环境自己持有一个 `Generator`，或者用父类给的 `self.np_random`。

```python
class GridWorldEnv(gym.Env):
    def __init__(self):
        super().__init__()
        self.rng = np.random.default_rng(0)
```

第二个是忘了 `super().reset(seed=seed)`。gymnasium 的基类会在这一步里初始化 `self.np_random`，跳过它，你的环境拿不到种子，两次 `reset(seed=0)` 结果不一样，而检查器会报一个不太直观的错。

第三个是把观测的类型搞错。`Discrete` 空间接受整数，如果你的 `step` 返回的是 `numpy.ndarray` 或者 `numpy.float64`，检查器会报“观测不在空间里”。转一下类型就好。

第四个是 `step` 返回四元组。老接口是四个值，新接口是五个，加了一个 `truncated`。自己写的时候容易照着记忆写四个，然后被 `check_env` 抓住。

第五个是把内部状态泄漏出去。`reset` 和 `step` 返回的观测如果是内部数组的引用，调用方改了它，环境的状态就跟着变了。用小环境时不容易发现，用 numpy 数组做观测的大环境上会出很诡异的 bug。返回之前拷一份，成本很低。

这五条里前四条检查器能拓住，后两条拓不住。泄漏状态的错误要靠自己读代码或者刻意的压力测试，比如把同一个观测拿去反复改，看看环境的行为会不会跟着变。

这五个坑有一个共同点，它们都不会让程序崩掉，只会让结果不对。所以写完环境之后，先跑一遍检查器，再跑一遍随机的轨迹打印出来看，两分钟能省下半天。

### 观测空间用哪种

把状态编号成整数之后，观测空间自然写成 `Discrete(40)`。这是最直接的做法，但它会限制你能接什么算法。

表格方法喜欢离散观测，因为可以直接拿去索引。神经网络不喜欢，因为 `Discrete` 给的是一个整数，网络需要向量。把整数转成向量的常见做法有两种，一种是独热，一种是嵌入。四十个状态独热就是四十维，能用，但地图一大就爆了。

如果一开始就想要跟深度方法兼容，可以声明成 `Box`，把编号包成形状为 `(1,)` 的浮点数组。

```python
self.observation_space = spaces.Box(low=0, high=self.inner.obs_dim - 1,
                                    shape=(1,), dtype=np.float32)
```

代价是表格方法这边多一层转换，`int(obs[0])` 才能拿到索引。两种写法都能跑，选哪个看你后面想接什么。本书的做法是两套并存，表格实验用 `Discrete`，深度实验用 `Box`，转换只在入口处做一次。

还有第三种选择，把观测写成多维的 `Box`，每一维对应地图的一个属性。比如状态里同时放行列坐标和到终点的曼哈顿距离，形状就是 `(3,)`。这样网络能直接看到距离，学起来快，但你等于把一部分解题信息送给了它。这种“帮算法一把”的做法在工程上很常见，在研究中要小心，因为它会把难度降低到看不出算法本身的差别。
