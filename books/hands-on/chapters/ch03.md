## 看懂一条轨迹

训练一个智能体，本质上是在处理一堆轨迹。每条轨迹是一串观测、动作和奖励。把这条数据流的组织方式弄清楚，后面读算法代码会轻松很多。

### 一次交互的五个返回值

```python
obs, reward, terminated, truncated, info = env.step(action)
```

这五个值里，最容易搞混的是中间两个。很多老代码把它们合成一个 `done`，结果在计算回报时埋下隐患。

`terminated` 表示任务真的结束了。杆子倒了，游戏输了，机器人掉沟里了，这些属于真正的终止。终止之后的状态没有未来，从这里往后算回报是没有意义的。

`truncated` 表示时间到了。任务本身没有结束，只是被外部限制掐断。比如 CartPole 的五百步上限，到了就停，但杆子还立着。这种情况下，那个状态其实还有未来，只是我们没继续往下走。

这个区别会影响回报的计算。算目标值时，如果下一步是终止，后面的价值要归零；如果是截断，后面的价值应该保留，因为世界还在继续。很多初学者写的代码在这里统一当成终止，结果学出来的策略偏保守，因为它把“时间到了”误认为“完蛋了”。

### 五个返回值各自的类型

类型这件事看着琐碎，动手时却是最常见的坑。

观测是一个 numpy 数组，dtype 通常是 float32。奖励是 Python 的 float，不是 numpy 的标量类型，虽然打印出来看不出区别。判断终止和截断的两个值是布尔值，`bool` 而不是 `np.bool_`。附加信息是字典。

写代码时可以顺手断言一下，成本很低，能挡住一整类错误。

```python
import numpy as np

obs, reward, terminated, truncated, info = env.step(action)

assert isinstance(obs, np.ndarray), type(obs)
assert obs.dtype == np.float32, obs.dtype
assert isinstance(terminated, bool), type(terminated)
assert isinstance(truncated, bool), type(truncated)
assert isinstance(info, dict), type(info)
```

这些断言在官方的环境里永远通过，在你自己写的环境里很容易挂。挂了是好事，说明你的环境接口和标准不一致，后面的工具（比如向量化环境、录制器）用上去会出更奇怪的问题。

还有一个细节。`terminated` 和 `truncated` 有可能同时为真。跑到最后一步正好踩到终点，同时又正好撞上步数上限，这种情况报错了两件事。写代码时不要假设两者互斥，判断结束用或，判断语义用与。

```python
done = terminated or truncated          # episode is over
real_end = terminated and not truncated # the world itself ended
```

第二行这种写法只在需要区分时用。多数时候你只关心第一行。

### 终止还是截断，一张对照表

两个布尔值的差别可以用一张表固定下来，写训练循环时照着核对。

::: {.tabcap}
表 3-1　终止与截断的区别
:::

| 项目 | terminated | truncated |
| --- | --- | --- |
| 谁决定的 | 任务规则 | 外部限制 |
| 典型触发 | 杆子倒了，走进陷阱，到达终点 | 步数上限，时间上限，外部中断 |
| 后面还有未来吗 | 没有 | 有，只是没继续走 |
| 算目标值时 | 未来项取零 | 未来项保留，用自举补上 |
| 样本进经验池时 | 标记为回合末尾 | 标记为普通转移或切断 |
| 当成另一种处理 | 会把“没走完”学成“走完了”，价值偏低 | 会把“结束”学成“还有未来”，价值偏高 |

最后一行是这张表的价值所在。把截断当终止，价值系统性偏低，学出来的策略偏保守。把终止当截断，价值系统性偏高，算法会以为死了还能复活，学出来的策略会往危险的地方凑。两种错都不报错，只是曲线难看，所以只能靠这张表提前防住。

### 一段真实的轨迹

下面是从 CartPole 里抽出来的八步，随机策略，种子固定。

```text
t=0 a=1 pos=-0.042 vel=+0.168 ang=+0.030 av=-0.275 r=1
t=1 a=0 pos=-0.039 vel=-0.027 ang=+0.025 av=+0.027 r=1
t=2 a=0 pos=-0.039 vel=-0.223 ang=+0.025 av=+0.328 r=1
t=3 a=0 pos=-0.044 vel=-0.418 ang=+0.032 av=+0.628 r=1
t=4 a=0 pos=-0.052 vel=-0.614 ang=+0.044 av=+0.931 r=1
t=5 a=1 pos=-0.064 vel=-0.419 ang=+0.063 av=+0.652 r=1
t=6 a=1 pos=-0.073 vel=-0.225 ang=+0.076 av=+0.380 r=1
t=7 a=1 pos=-0.077 vel=-0.031 ang=+0.084 av=+0.112 r=1
```

可以看到第 1 到第 4 步一直往左推，杆子开始往一个方向偏，角速度从正的零点零三涨到零点九三。第 5 步换成往右推，角速度开始回落。这正是“根据状态调整动作”的样子。

注意观测里的数字都是连续的，而且数值范围各不相同。位置在正负五左右，角度在零点几，速度可能到几。这种量纲差异对神经网络不友好，实践中常常要做归一化。CartPole 的数值范围还算温和，所以很多教程直接喂进去也能学。

这段轨迹是可以复现的，种子是三，动作序列是一、零、零、零、零、一、一、一。想自己跑一遍，改几行就够。

```python
import gymnasium as gym
import numpy as np

env = gym.make("CartPole-v1")
obs, _ = env.reset(seed=3)
print("start", np.round(obs, 4))
for a in (1, 0, 0, 0, 0, 1, 1, 1):
    obs, r, terminated, truncated, _ = env.step(a)
    print("a=%d" % a, np.round(obs, 4), "r=%.0f" % r,
          "term", terminated, "trunc", truncated)
```

顺带一提，这段轨迹里 `terminated` 和 `truncated` 全是假。八步之后杆子还没倒，回合还在继续。一条轨迹往往只有最后一帧才出现其中一个真值，前面几百帧都是假。这也解释了为什么写训练循环时容易忘记处理这两个标志，因为大多数时候它们确实不影响任何东西。

### 手算一遍折扣回报

回报是把一串奖励折算成一个数。从后往前累加是最不容易错的办法。

```python
def discounted_returns(rewards, gamma=0.99):
    out = [0.0] * len(rewards)
    running = 0.0
    for i in reversed(range(len(rewards))):
        running = rewards[i] + gamma * running
        out[i] = running
    return out
```

以刚才那八步为例，每一步奖励都是 1，最后一步的回报是 1，倒数第二步是 1 + 0.99 = 1.99，第一步是这些数的加权和，约等于 7.73。整个过程不需要知道后面有多少步，从尾巴开始往前推就行。

把八个数全列出来，能看清结构。

```text
末尾往前  0.99 的幂   累计
1.0000    0.99^0      1.0000
1.9900    0.99^1      1.9900
2.9701    0.99^2      2.9701
3.9404    0.99^3      3.9404
4.9010    0.99^4      4.9010
5.8520    0.99^5      5.8520
6.7935    0.99^6      6.7935
7.7255    0.99^7      7.7255
```

第三列的每一行都是前三项之和的折现，数值上等于 `(1 - 0.99^k) / 0.01`。这组数有一个明显的规律，越往后越挤，从 7.73 到 6.79 掉了零点九三，从 2.97 到 1.99 掉了零点九八。差距接近一，说明每一步的增量本身被折现到几乎为零。

这正是折扣因子的意义。它把无限长的未来压成一个有限的数。八步之和的极限是 `1 / 0.01 = 100`，也就是说哪怕每一步都给一分，回报也不会超过一百。这个上限让价值函数有一个确定的取值范围，算法调参数时心里有数。

换个折扣因子，同一段奖励会算出完全不同的数。零点九五时八步的总回报是 6.7316，比零点九九时少了将近一。折扣因子越小，算法越看重眼前，越不愿意为远处的奖励等待。

手算这件事的价值在于建立直觉。看代码时 `running = reward + gamma * running` 只是一行，但你知道它在算的是这条尾巴的加权和，而且知道权重的形状是一条指数衰减曲线。

### 对齐这件事

算回报时最容易出错的地方不是折现，而是下标。奖励、动作、观测三个数组的长度天然不一样，差一位，整个回的计算就错了。

一条跑了 T 步的轨迹里，观测有 T 加一个，因为第一步之前有一个初始观测。动作有 T 个，奖励也有 T 个。收益有 T 个，对应每个动作之后的那段尾巴。

```python
traj = {"obs": obs_list, "act": act_list, "rew": rew_list}
assert len(traj["obs"]) == len(traj["act"]) + 1
assert len(traj["rew"]) == len(traj["act"])
```

这两行断言很土，但它们能拓住一整类错。如果没有它们，把 `rew[i]` 和 `obs[i]` 对错了，代码不报错，算出来的回报也看不出异常，只是策略学得慢一点。

还有一种更隐蔽的错位。有人的循环里先 `step` 再收奖励，有人的循环里先收奖励再 `step`。两种写法都对，但混用时就会错一位。表现是回报的第一个值比应有的少一个奖励，而结尾多了一个零。这种错在长轨迹上很不显眼，因为一位的差别被折现压得很小，但它在教算法一件事，上一步的奖励属于下一步。

### 回报的三个变体

回报这个词在不同的地方指不同的东西，混用会读不懂代码。

第一个是整条轨迹的回报，也就是从第一步算到结束的一个数。评估策略时用的就是它。

第二个是从某一步开始的回报，也叫收益。轨迹中第 t 步的收益，是从 t 开始往后所有奖励的折现和。上面那张表的第三列就是每一步的收益。

第三个是价值，也就是收益的期望。给定状态之后，按某个策略走下去，平均能拿到多少。前两个是从一条具体轨迹里算出来的实际值，第三个是统计意义上的平均值。

三者的关系可以用一句话概括，一条轨迹里的收益是价值的采样，价值是无数条轨迹里收益的平均。这也解释了为什么策略梯度的方法方差大，因为它在用单个样本来估计期望。

还有一个量叫优势，等于某个动作的收益减去这个状态的平均价值。它回答的是“这个动作比平均水平好多少”。第七章讲策略梯度时会用到，现在只需要知道它来自收益和价值的差。

### 轨迹存下来是什么样

训练时我们会把每一步存成一串五元组，后面从里面抽样学习。

```python
transition = (obs, action, reward, next_obs, terminated)
buffer.append(transition)
```

这里存的是 `terminated` 而不是 `truncated`，因为学习目标只关心任务是否真的结束。截断的情况在下一轮采样时会重新出现，不需要特殊处理。

上面这种存法在演示代码里很常见，到了真实训练就不够用了。一个元组里混着 numpy 数组和标量，几万条之后内存碎片严重，按字段取一列还要循环。换成一组并行的数组，读写都快得多。

```python
class Buffer:
    def __init__(self, capacity, obs_dim):
        self.obs = np.zeros((capacity, obs_dim), dtype=np.float32)
        self.next_obs = np.zeros((capacity, obs_dim), dtype=np.float32)
        self.action = np.zeros(capacity, dtype=np.int64)
        self.reward = np.zeros(capacity, dtype=np.float32)
        self.done = np.zeros(capacity, dtype=np.float32)
        self.ptr = 0

    def add(self, obs, action, reward, next_obs, terminated):
        i = self.ptr % len(self.reward)
        self.obs[i] = obs
        self.next_obs[i] = next_obs
        self.action[i] = action
        self.reward[i] = reward
        self.done[i] = float(terminated)
        self.ptr += 1

    def sample(self, batch, rng):
        idx = rng.integers(0, min(self.ptr, len(self.reward)), batch)
        return (self.obs[idx], self.action[idx], self.reward[idx],
                self.next_obs[idx], self.done[idx])
```

这段代码里有三个细节值得说。用固定大小的数组环形覆盖，内存不会随训练增长。观测统一成 float32，省一半内存。抽样返回的是一整批数组，可以直接转成张量，不需要 Python 循环。

`done` 存成浮点数零或一，是为了后面能直接做乘法。`target = reward + gamma * (1 - done) * max_q`，比写 if 分支快，也更容易向量化。

如果要把整条轨迹的回报算出来，从后往前累加是最简单也最不容易错的办法。

```python
def returns_to_go(rewards, gamma=0.99):
    out = np.zeros(len(rewards), dtype=np.float32)
    running = 0.0
    for i in reversed(range(len(rewards))):
        running = rewards[i] + gamma * running
        out[i] = running
    return out
```

这比逐步调用 `discounted_returns` 快，因为它只在最后写一次数组。整条轨迹几千步时，差别可以到几倍。

### 把截断当终止，价值会低多少

这个错误到底有多严重，可以量一下。

造一条十二格的走廊，起点在最左边，终点在最右边，每走一步扣零点零一，走到终点得一分并结束。训练时把回合截断在二十步，所以经常走不到终点。策略固定为一个六成往前、四成往后的随机策略，然后用时序差分学价值函数。两种写法唯一的差别是截断处的目标值算不算未来。

折扣因子零点九五，二十步的折现是 0.3585。也就是说被截断的那一帧之后，还有超过三分之一的未来权重被砍掉了。

跑四万局之后，两种写法的价值估计和精确值对比如下。

```text
状态      精确值    正确自举    当成终止
起点     -0.0252    -0.0233    -0.0936
第六格    0.2286     0.2369     0.0144
第十格    0.6805     0.6795     0.4110
最后一格  0.8546     0.8649     0.7235
```

正确自举的那一列几乎贴着精确值，四个状态的误差都在零点零一以内，平均绝对误差 0.0068。当成终止的那一列整体往下沉，起点从负零点零二五掉到负零点零九四，最后一格从零点八五掉到零点七二，平均绝对误差 0.162，是前者的二十四倍。

差异的形状也有信息。越靠近终点，误差越大，因为越靠近终点的状态，被截断时“剩下的未来”越值钱。起点附近的误差相对小，因为从起点出发本来也走不到哪去。

价值偏低会带来什么后果，取决于算法怎么用这个价值。做策略评估时，它会让算法低估远处奖励的吸引力，策略变得短视。做控制时，如果所有状态都被等量压低，策略顺序不变，影响不大；如果压低得不均匀，就可能选错动作。上面这组数里，最后一格的相对排序没变，所以在走廊上贪心策略仍然对。换一个结构，比如有一个“快但奖励小”和一个“慢但奖励大”的岔路，压低不均匀就会选错。

有一个容易忽略的对应关系。截断越晚，误差越小。二十步的截断损失 36%，如果截断在五十步，折现只剩 0.077，误差就小得多。这也解释了为什么有些代码里这个 bug 存在很久也没被发现，因为他们的回合很长，截断很少发生。

### 截断在真实环境里有多常见

上面那个走廊是我造的，可能有人觉得不典型。看两个真实的数据。

CartPole 上那个手写控制器，一百局全部跑满五百步，全部是截断，没有一局真倒。如果训练数据全部来自这种策略，那么每一条轨迹的末尾都是截断。这时候把截断当终止，等于每条样本的最后一步都在教算法“走到这里就没未来了”。五百步里错一步，看着不多，但每一条轨迹都错，而且是错在最有信息量的那一步。

网格世界上的数据更细。把回合上限设成十三步，最短路是十一步，跑六百局。正确自举的版本里有三百六十三局被截断，学完之后贪心策略一百局全部成功，平均十一步。把截断当终止的版本里四百二十六局被截断，学完之后成功率也是一百，但起点状态的价值从 0.5185 掉到 0.5047。

这个结果值得说清楚。价值确实被压低了，低了百分之二点七，但策略没坏。原因是这张地图上每条路都能到终点，区别只在长短，价值被整体压低之后排序不变。所以这个 bug 的破坏力取决于任务结构，有的任务上它只是让数字难看，有的任务上它直接让算法学不会。你不能因为某次没出错就认为它无害。

### 正确写法长什么样

两种写法，取决于你在哪一层。

存样本的时候，只存 `terminated`，因为自举的判断要用它。这是最常见也最省事的做法。

```python
buffer.add(obs, action, reward, next_obs, terminated)
```

算目标值的时候，用 `terminated` 决定要不要加未来项。

```python
target = reward
if not terminated:
    target += gamma * np.max(Q[next_state])
```

如果样本的来源是被截断的回合，而且你想严格一点，那就把截断那一帧的后续价值补上。

```python
target = reward
if not terminated:
    target += gamma * np.max(Q[next_state])
if truncated:
    target += (gamma ** steps_to_cut) * value_at_cut
```

最后这一段在实践里很少人写，因为要知道从当前帧到截断点还有多少步，实现起来麻烦。更常见的近似是让回合足够长，让截断变成罕见事件。这是一种工程上的取舍，不是理论上的正确，但它在多数任务上够用。

还有第三种做法，在采样时就规避。如果一局是因为撞上步数上限而结束，那就把这一局整条丢掉，只用自然结束的局。这适合那些截断稀少的任务，代价是浪费样本。如果截断很频繁，这条路走不通，因为丢掉之后就没数据了。

### 轨迹有多长才够

一条轨迹要足够长，才能包含一个完整的行为。CartPole 一局通常几十到几百步，足够了。有些任务一局只有几步，比如猜拳，那就要把很多局拼起来看。

还有些任务没有自然的终止。服务器调度、持续的推荐流、在线的广告竞价，都是这样。这类任务通常按固定长度切段，或者按时间窗口处理。切段的位置会影响学习，切得太短，学不到长期影响；切得太长，训练慢而且方差大。

切段还有一个副作用，切出来的每一段末尾都是截断。前面刚讲过，截断处的处理方式会直接影响价值估计。所以做这种任务时，截断的处理不是可选项，而是必须想清楚的一环。我见过一些实现干脆在切段时不做任何标记，把每一段都当成独立的一局，那就是前面说的那个 bug，只是它藏得更深，因为数据来自“本来就没有终止”的任务。

### 一条轨迹里能读出什么

轨迹不只是算法的原料，也是排查问题的证据。一条轨迹至少能回答五个问题。

跑了多长。长度短得异常，说明策略在开局就崩，或者环境本身有问题。长度长得异常，说明策略在绕圈，或者回合上限太高。

回报是多少。和长度一起看，能判断奖励是否密集。CartPole 里回报等于长度，两者同步；如果长度长而回报低，说明任务给的是稀疏奖励，中间过程没有分。

动作分布。统计一下每个动作被选中的比例，能看出策略是不是退化了。两个动作各半是随机，九比一是几乎固定，真正学好的策略会根据状态变化，分布上可能是偏的，但在不同状态下方向不同。

访问过多少状态。把观测离散化之后数一数，能看出探索够不够。只访问了少数几个状态就宣布收敛，通常是因为策略卡死了。

最后一步是终止还是截断。这一个值决定了这条样本能不能用来学长期行为。

```python
def describe(traj, terminated, truncated):
    return {
        "length": len(traj["rew"]),
        "return": round(sum(traj["rew"]), 2),
        "act_share": float(np.mean(np.asarray(traj["act"]) == 1)),
        "states": len({tuple(np.round(o, 1)) for o in traj["obs"]}),
        "end": "terminated" if terminated else
               ("truncated" if truncated else "running"),
    }
```

跑出问题的时候，先打印这五个数，比看曲线快。曲线是统计后的结果，已经把单条的异常平掉了。

### 为什么要把轨迹打散

初学者常有一个疑问。既然轨迹是顺序产生的，为什么训练时要随机抽样，而不是按顺序学？

原因在数据相关性。连续几步的观测几乎一样，梯度方向也几乎一样。如果按顺序更新，参数会被同一个方向连续推很多次，容易过冲。更糟的是，网络会过度拟合最近这段经历，忘掉之前学过的内容。

随机抽样把相关性打散，每一批数据更像是独立采样。这个技巧在第七章讲 DQN（深度 Q 网络，Deep Q-Network，2013 年提出）时会详细说，它是让深度强化学习能跑起来的关键之一。

### 从轨迹到学习信号

有了轨迹，还要把它变成可以用来更新参数的东西。不同的算法用不同的方式。

基于价值的方法，从轨迹里抽出状态、动作、奖励、下一状态，算一个目标值，让网络的预测去逼近它。基于策略的方法，把整条轨迹的回报算出来，用它给每一步的动作加权，回报高的动作以后多出现。

这两条路的差别在于更新目标里用了哪一个量。这里只需要建立一个印象：轨迹是原料，算法是加工方式，最后都指向同一件事，让好的行为更常出现。

两类方法可以混着用。学一个价值函数专门用来给策略降方差，或者用策略去采集更有针对性的数据，再把数据当成价值方法的原料。这条路线在后面几章会反复出现，现在不用管细节，只要知道自己手里的原料只有一样东西，就是轨迹。轨迹怎么来、怎么存、怎么用，弄清楚了，所有算法都是同一条流水线上的不同环节。
