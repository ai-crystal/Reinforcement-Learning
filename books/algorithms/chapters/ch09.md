## Actor-Critic 与广义优势估计

策略梯度用回报加权，方差大。价值方法用自举，偏差大。把两者接起来，就得到演员评论家结构。

这一章讲这个结构怎么工作，以及它的关键零件，优势估计。

### 两个网络，两种角色

演员（actor）是策略 $\pi_\theta(a\mid s)$，负责选动作。

评论家（critic）是价值函数 $V_\phi(s)$，负责评价当前状态有多好。

训练时，演员按评论家给出的评价调整，评论家按实际观察到的回报调整。两者互相依赖，一起进步。

名字的来历值得一提。演员负责行动，评论家负责打分，这个比喻出自神经科学里对基底核的观察，后来被搬到强化学习里。比喻贴切的地方在于，两者确实是一个闭环，谁离开谁都不成立。

这个结构解决了一个具体的麻烦，信用分配。原始的策略梯度只能用整条轨迹的回报给每一步打分，有了评论家，每一步都能拿到“当前状态本来该值多少”的参照，回报减去这个参照就是这一步的额外贡献。

它的代价是多了一个要训练的网络。两个网络互相依赖，就有了一个新的不稳定来源，评论家错了演员跟着错，演员变了评论家的数据分布也变。这就是为什么演员评论家在实践中需要更多技巧，比如不同的学习率、目标网络、梯度裁剪。

还有一个隐含的好处，可以单步更新。原始策略梯度必须等回合结束才能算回报，演员评论家每走一步就能算误差、更新一次。这让它可以使用持续任务，也让数据利用率高很多。

$$
\theta \leftarrow \theta + \alpha\,\nabla_\theta\log\pi_\theta(a\mid s)\,\hat{A}(s,a)
$$

$$
\phi \leftarrow \phi - \beta\,\nabla_\phi\left[\hat{R} - V_\phi(s)\right]^2
$$

$\hat{A}$ 是优势的估计，$\hat{R}$ 是回报的目标。评论家越准，演员的梯度越可靠；演员越好，评论家见到的数据质量越高。

### 两种角色的分工

把两个网络看成两个不同的任务，就清楚该怎么给资源。

评论家做的是回归。它的标签是从数据算出来的，虽然有噪声，但方向明确。这类任务收敛快，可以用大一点的学习率，也可以承受大一点的网络，因为它不会反过来改变数据分布。

演员做的是策略改进。它的“标签”来自优势，而优势依赖于评论家，本身带有偏差。它的更新会改变数据分布，所以必须保守。学习率小一点，更新频率低一点，才不容易崩。

实践中的经验值，评论家学习率是演员的三到十倍。共享主干时，两者的学习率差会体现在梯度冲突上，这时候要额外加梯度裁剪或者干脆分开。

还有一点，评论家的输出尺度要关注。它的损失是平方误差，回报大一千倍，损失大一百万倍，学习率必须跟着变。这也是为什么奖励归一化几乎是必做项。

### 评论家怎么学

评论家的任务比演员简单，它只是拟合一个函数，目标是从数据里算出来的回报。不需要探索，不需要处理分布偏移。但它有一个陷阱，目标也在动。

最直接的写法是一步时序差分。

$$
\phi \leftarrow \phi + \beta\left[r + \gamma V_\phi(s') - V_\phi(s)\right]\nabla_\phi V_\phi(s)
$$

这是第六章讲过的半梯度，梯度只从 $V_\phi(s)$ 流回，目标里的 $V_\phi(s')$ 不求导。损失写成平方误差的形式，框架会自动算这一项。

也可以直接用多步回报或者完整回报当目标，代价是方差大。实践中常用折中，取十几步的回报，或者用下一章讲的广义优势估计反推目标。

```python
with torch.no_grad():
    next_v = critic(next_obs)
    target = reward + gamma * next_v * (1.0 - done)
v = critic(obs)
critic_loss = torch.nn.functional.mse_loss(v, target)
```

三处容易错。`done` 必须只包含真终止，截断不能算进去。目标的计算必须在 `no_grad` 里，否则会不小心把梯度也传到目标网络上。价值输出的形状要和奖励对齐，多一维少一维都会广播成奇怪的形状而不报错。

评论家准不准，可以直接看它的损失。损失降不下去，说明特征不够或者学习率不对；损失很小但演员学不好，说明优势的估计方式有问题，不是评论家的问题。

### 优势的三种估计

先把三种估计的差别说清楚。它们的区别只在“往回看多远”，而看多远决定了偏差和方差各占多少。

一步估计只看一步，剩下的全部交给价值函数。价值准，它就准；价值不准，它就把错误原样继承下来。它的问题是奖励信号传得慢，一个奖励要经过很多次更新才影响得远处的状态。

完整回报看一整局，不依赖价值函数，无偏。代价是方差，一局里所有随机性都算在这一个数上。

中间那些看几步的做法，是在两者之间取一个点。取几步合适，取决于任务：奖励稀疏就要多看几步，否则奖励传不回来；噪声大就要少看几步，否则方差压不住。

最简单的是用一步的时序差分误差。

$$
\hat{A}_t^{(1)} = r_{t+1} + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)
$$

它的期望是优势的一个有偏估计，偏差来自 $V_\phi$ 不完美，但方差很小。

偏差具体有多大，可以估一下。设价值函数在两个相邻状态上的误差分别是 $e_t$ 和 $e_{t+1}$，那么一步优势的偏差约是 $\gamma e_{t+1}-e_t$。两个误差如果同向，这一项不会抵消，所以价值曲面的整体偏移会原封不动地传进优势。

这也是为什么评论家的损失降得很低，不代表优势就准。损失小只说明它拟合了数据，数据本身可能有偏。

另一种是用完整的蒙特卡洛回报减去价值。

$$
\hat{A}_t^{(\infty)} = G_t - V_\phi(s_t)
$$

无偏，但方差大。

方差大在哪里，可以说得具体些。它的方差约等于回报的方差，而回报的方差随回合长度线性增长。回合一百步、每步奖励方差一，回报方差就是一百，标准差十。优势的真实量级往往只有零点几，信噪比差两个数量级。

这就是为什么直接用完整回报当优势，梯度几乎全是噪声。必须靠大量样本平均，或者靠自举把方差压下来。

中间的做法是看 $n$ 步。

$$
\hat{A}_t^{(n)} = \sum_{k=0}^{n-1}\gamma^k r_{t+k+1} + \gamma^n V_\phi(s_{t+n}) - V_\phi(s_t)
$$

$n$ 越大，偏差越小，方差越大。这个取舍和 TD($\lambda$) 完全一样，只是换了个名字。

### 把这些估计串起来

三种估计不是并列的选项，而是一条连续的线。把 $n$ 步优势写成一步误差的和，就能看清这条线。

$$
\hat{A}_t^{(n)} = \sum_{k=0}^{n-1}\gamma^k\delta_{t+k}
$$

$\delta_t = r_{t+1}+\gamma V(s_{t+1})-V(s_t)$ 是一步误差。两步的优势等于第一步的误差加打折的第二步误差，三步再加一项，依次类推。这个展开把“走几步再自举”翻译成了“累加几个误差”。

验证一下 $n=1$ 的情形，右边只有 $\delta_t$，就是一步估计。$n$ 趋于无穷时，所有误差累加，中间的价值项两两抵消，只剩下真实回报减当前价值，就是蒙特卡洛。中间每个 $n$ 对应一项截断。

有了这个形式，广义优势估计就很好理解。它对所有 $n$ 取指数加权平均，权重是 $(1-\lambda)\lambda^{n-1}$。把求和交换顺序之后，同一个 $\delta_{t+k}$ 会被后面所有项重复计入，权重累加起来正好是 $(\gamma\lambda)^k$。

$$
\hat{A}^{\text{GAE}}_t = \sum_{k=0}^{\infty}(\gamma\lambda)^k\delta_{t+k}
$$

这就是那个双重折扣的来源。$\lambda$ 每往后一步衰减一次，$\gamma$ 也每步衰减一次，两者相乘。它和第四章的 TD($\lambda$) 是同一个东西，只不过那里的回报换成了这里的优势。

顺带一个不等式，$\gamma\lambda$ 永远小于一，所以求和一定收敛。这一点在原公式里不明显，因为它写的是无穷和。

偏差和方差的取舍也变得很清楚。$\lambda$ 小，只有近处的误差进来，方差小偏差大。$\lambda$ 大，远处的误差也进来，方差大偏差小。$\lambda$ 为零时退化成一步，$\lambda$ 为一且价值准确时无偏。

### 广义优势估计

GAE（generalized advantage estimation，广义优势估计，2016 年提出）把这几个 $n$ 步估计按指数加权平均。

$$
\hat{A}^{\text{GAE}(\gamma,\lambda)}_t = \sum_{l=0}^{\infty}(\gamma\lambda)^l\,\delta_{t+l}
$$

其中 $\delta_t = r_{t+1}+\gamma V(s_{t+1}) - V(s_t)$ 是时序差分误差。

$\lambda=0$ 时只剩第一项，退化成一步估计。$\lambda=1$ 时变成蒙特卡洛。通常取零点九五，偏向方差小的一端。

这个式子里 $\infty$ 的上限实际是回合结束，因为回合结束之后误差项为零。所以严格说它是一个有限和，只是长度不固定。

为什么要用递推而不是直接求和。直接求和要为每个时刻遍历到回合结束，复杂度是回合长度的平方。递推从后往前一次扫完，复杂度线性，而且可以在线维护。

递推的写法利用了一个恒等式。$t$ 时刻的优势等于当前误差加上打折的下一时刻优势，也就是 $\hat{A}_t = \delta_t + \gamma\lambda\hat{A}_{t+1}$。一行代码就能实现，这就是为什么 GAE 在工程上如此流行。

```python
last = 0.0
for t in reversed(range(n)):
    nonterminal = 1.0 - dones[t]
    delta = rewards[t] + gamma * values[t + 1] * nonterminal - values[t]
    last = delta + gamma * lam * nonterminal * last
    adv[t] = last
```

这段代码只有五行，但它把偏差和方差的平衡变成了一个参数。PPO（proximal policy optimization，近端策略优化，2017 年提出）效果好，GAE 功不可没。

### 一个批处理版本

上面那五行是单条轨迹的写法。实际训练要同时处理一批长度不一的轨迹，需要额外的掩码。

```python
def compute_gae(rewards, values, dones, gamma=0.99, lam=0.95):
    # rewards, values: (T, N), values has T+1 rows
    adv = torch.zeros_like(rewards)
    last = torch.zeros(rewards.shape[1])
    for t in reversed(range(rewards.shape[0])):
        nonterminal = 1.0 - dones[t]
        delta = rewards[t] + gamma * values[t + 1] * nonterminal - values[t]
        last = delta + gamma * lam * nonterminal * last
        adv[t] = last
    returns = adv + values[:-1]
    return adv, returns
```

三处关键。`nonterminal` 在回合结束时把自举截断，这一步漏了会让所有轨迹末尾的优势偏高。`last` 每列独立，因为不同环境在不同时刻结束。`returns` 是优势加价值，这是评论家的回归目标，用它当目标比用原始回报更稳，因为它含了自举的信息。

代码里没有出现的两件事也值得说。优势通常要做批内标准化，减去均值除以标准差，否则不同批次之间尺度不一致。价值目标有时也要裁剪，防止一次更新把价值推太远。

### 为什么是双重折扣

指数加权的系数是 $\gamma\lambda$，不是 $\lambda$。原因是每一步的时序差分误差本身已经被 $\gamma$ 折扣过，再乘一次 $\lambda$ 就是双重折扣。

这个形式还有一个解释，它等价于把 $\lambda$ 看成“每多走一步，信任度下降多少”。$\lambda$ 等于零点九五，意味着十步之外的误差只保留六成权重。

### 一个误差能传多远

用一个小例子看这个系数的作用。$\gamma$ 取零点九九，$\lambda$ 取零点九五，乘积零点九四。误差传到第十步，权重是零点九四的十次方，约零点五四；传到第二十步，约零点二九；传到第五十步，不到百分之五。

换成 $\lambda$ 等于零，第二步的权重就是零，误差只影响当前这一步。换成 $\lambda$ 等于一，权重变成 $\gamma$ 的幂，第五十步还有零点六一。

这解释了为什么 $\lambda$ 对稀疏奖励任务这么关键。奖励在第五十步才出现，$\lambda$ 小的时候它对当前决策几乎没有影响，智能体学不到“提前准备”。

### λ 怎么选

先说结论，零点九五到零点九九是常用范围，Atari 和 MuJoCo 上的经典配置都在这里面。

选的理由和任务长度有关。回合只有几十步，$\lambda$ 取零点九就够，因为远端的误差本来也没几项。回合几百上千步，$\lambda$ 要接近一，否则远处的事件传不回来。

还有一件事要一起调。$\lambda$ 大了方差大，学习率要跟着降；$\lambda$ 小了偏差大，价值函数要学得更准。单独调一个往往没有效果，因为另一个在拖后腿。

### 训练中的问题

演员和评论家一起训练，会互相干扰。

评论家不准的时候，演员的梯度方向也是错的。演员变化太快的时候，评论家的目标跟着变，学不稳。

常见的处理方式是给两者不同的学习率，通常评论家学得快一些，因为它的任务更简单。也有的实现共享底层特征，只在输出层分开，这样能省参数，但两者的更新会互相影响。

另一个问题是价值估计的尺度。不同任务的回报范围差别很大，价值网络的输出可能很大也可能很小，导致损失的量级差异明显。常见的做法是对回报做标准化，或者用 Huber 损失限制大误差的影响。

### 三个不稳的来源

第一个是共享主干。演员和评论家共用卷积层或 Transformer 时，两个损失的梯度会打架，一个想把特征拉向“有利于分类动作”，另一个想拉向“有利于回归价值”。表现是训练前期价值损失降得很慢。常见的处理是给价值头单独几层，或者干脆不共享。

第二个是优势的尺度。同一批数据里，优势的分布可能非常偏，少数极大值主导梯度。标准化能缓解，但它改变了“这个动作到底比平均好多少”的绝对信息，有些实现只在演员损失里做标准化，评论家那边用原始值。

第三个是截断的处理。回合被时间上限切断时，如果按终止处理，价值会学到“到时间就没奖励了”，这种偏差会随着训练累积。正确做法是在截断处继续自举，把“未来还可能发生”的信息保留下来。

这三个问题的共同点是，它们都不会让训练立刻崩，只会让曲线慢一点、差一点。所以很多人查不出来，只能靠对比实验确认。

### 一个常见的误解

有人把 GAE 当成“优势的一个定义”。它不是定义，是一种估计方式。优势的定义只有一个，动作价值减状态价值。GAE 是用时序差分误差拼出来的一个估计量，只是在特定条件下等于真优势。

这个区别有实际后果。$\lambda$ 变了，优势的估计就变了，即使策略和价值都没变。所以同一个算法换个 $\lambda$，学到的策略可能不一样，这不是 bug，是估计量不同带来的偏差差异。

另一个误解是“$\lambda$ 越大越准”。只在价值函数完全准确时成立。价值不准的时候，长视野的估计会把价值的错误也带进来，反而更差。所以在训练早期，$\lambda$ 小一点往往更稳。

### 一个训练循环长什么样

把零件拼起来，一次迭代大致是这样。

```python
for it in range(iterations):
    logps, rewards, dones, values, obs_all = collect(env, actor, critic, steps=2048)
    adv, returns = compute_gae(rewards, values, dones, gamma, lam)
    adv = (adv - adv.mean()) / (adv.std() + 1e-8)
    for epoch in range(10):
        for batch in minibatches(obs_all, logps, adv, returns):
            new_logp = actor.log_prob(batch.obs, batch.actions)
            ratio = torch.exp(new_logp - batch.logp)
            actor_loss = -(torch.min(ratio * batch.adv,
                                     ratio.clamp(0.8, 1.2) * batch.adv)).mean()
            critic_loss = torch.nn.functional.mse_loss(critic(batch.obs), batch.returns)
            loss = actor_loss + 0.5 * critic_loss
            optimizer.zero_grad(); loss.backward()
            torch.nn.utils.clip_grad_norm_(params, 0.5)
            optimizer.step()
```

这几行里已经包含了下一章的核心，裁剪。先用 GAE 算优势，再把同一批数据反复用来更新，靠裁剪限制每轮改动多少。批大小、轮数、裁剪范围的典型值是两千步、十轮、零点二。

注意 `batch.logp` 是采集时记录下来的旧对数概率，不能重新算。重新算等于用新参数去估旧策略，比值恒为一，裁剪就失效了。这个错误很常见，而且不报错。

### 和 DQN 的关系

演员评论家和 DQN 看起来差别很大，其实有共同点。

两者都用自举估计未来价值，都需要目标网络或者类似的稳定手段，都会遇到函数逼近加离轨加自举的组合。

区别在动作的选择方式。DQN 通过对每个动作求 Q 值再取最大，只能处理离散动作。演员评论家直接输出动作分布，连续离散都能做。

还有一点区别在探索。DQN 靠 $\epsilon$-贪心，探索是外加的。演员评论家的策略本身带随机性，探索是内在的。后者在连续动作上更自然，因为给一个连续动作加噪声比枚举更容易。

### 和策略梯度的关系

演员评论家不是策略梯度的替代品，而是它的一个改进版本。梯度的形式没变，还是对数概率乘优势，变的只是优势怎么算。

原始版本用完整回报减基线，演员评论家换成自举的估计。这一步把方差压下来，代价是引入偏差。GAE 在中间提供了一整条可调的路。

所以可以把这三章看成同一个东西的三个视角。第八章讲梯度从哪来，第九章讲优势怎么估得更准，第十章讲步长怎么限制。三件事拼起来，就是现在主流的策略优化算法。

顺带说一句，这种“同一个算法在不同书上名字不同”的情况在强化学习里很常见。看到新名字先看它的更新式，往往能认出老朋友。

### 出错时先看哪个

演员不涨的时候，先看评论家。评论家的损失如果一直降不下去，或者降下去但价值明显偏离真实回报，那么演员的梯度就是噪声。判断办法是算一下优势的均值，训练正常时它应该接近零，因为优势是相对平均水平的差。均值明显不为零，说明价值整体偏高或偏低。

再看演员的熵。熵迅速掉到很低，说明策略过早确定，探索不足，通常是学习率太大或者熵正则太小。熵一直很高不掉，说明梯度太弱，可能是优势太小或者归一化把信号压没了。

最后看裁剪比例。如果一批数据里超过一半被裁掉，说明策略一次走得太远，要减小学习率或者减少轮数。反之几乎没有被裁，说明限制没起作用，可以适当放大步长。

这几个指标一起看，比只盯回报曲线有效得多。回报是多步之后的间接结果，出问题时已经晚了。

演员评论家解决了样本效率的一部分问题，但没解决更新幅度的问题。一次梯度步仍然可能把策略推得很远。

再补一句关于顺序的建议。读这一章时可以先把 GAE 当成一个黑盒，只要接受“它是一组可调的、介于一步和完整回报之间的优势估计”，剩下的内容都能读懂。等真正要调参或者复现时，再回头看那个递推式。这样不容易被公式拦住。

补一句为什么这件事这么难。策略的更新幅度不是学习率能完全控制的，因为同样的参数步长，在不同状态下造成的概率变化可能差几十倍。一个状态下概率从零点五变到零点五一，另一个状态下从零点零一变到零点零二，后者是翻倍。所以限制更新必须看概率的变化，而不是参数的变化。

这句话也可以反过来说，同样的概率变化，对应的参数步长在不同状态下不一样。这就是为什么 PPO 的裁剪作用在比值上而不是参数上，也是为什么 KL 散度要用状态的分布去加权平均。约束的对象始终是行为，不是参数。

下一章的两个算法专门处理这件事。TRPO（trust region policy optimization，信赖域策略优化，2015 年提出）用约束，PPO 用裁剪，目标都是让新策略不要离旧策略太远。
